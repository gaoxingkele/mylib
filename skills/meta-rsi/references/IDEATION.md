# 思考算子目录：想法从哪来

`config/ideation.json` 的说明。metaRSI 不产生想法；它要求每条想法写明来自哪个算子、依据什么原理或视角、什么观测能推翻它，并统计各层算子在项目里的产出。这里解释每一层为什么在目录里、怎么用、常见的假动作。

## 为什么不止组合

把两个已验证的机制并置，是最省力的改进方式，也是审查员最容易用「常规组合」驳回的方式。真正改变问题的想法通常来自换一个描述问题的框架：换一个守恒量、换一个被控对象、换一个「谁在用」的假设。目录的五个层次就是五类框架。

## L1 组合与调参

不禁止，但要会识别。`L1.combine` 的问句是：并置之后有没有一个只在并置时才出现的量或约束？没有就是罗列。`L1.tune` 的问句是：参数有没有物理上界或下界？有的话去 L2 找。

## L2 科学第一性原理

| 算子 | 问 | 得到 |
|---|---|---|
| 守恒与收支 | 写出收支方程，每一项谁可观测？不可观测的那一项能否安排一个时段让它退出方程 | 新的标定窗口、可消去项 |
| 极限与量纲 | 参数推到 0 和无穷；哪个无量纲数决定行为 | 适用边界、阈值的物理取法 |
| 物理与信息上界 | 热力学、香农、采样定理各给什么上界 | 保守估计量、上界型门控 |
| 时间尺度分离 | 列出时间常数，相差一个量级的解耦 | 窗口长度、冻结与更新时机 |
| 对称与破缺 | 哪种对称让干扰相消，哪种不对称携带信息 | 差分驱动、以不对称为特征的检测量 |
| 不变量与比值 | 同一程序下的比值能否消去系统误差 | 自参照判据 |
| 因果方向反转 | 被控量与被测量互换 | 控制目标重选 |
| 限速步 | 链条里最慢、最不确定的一步 | 资源集中到瓶颈 |
| 可观测性与可控性 | 哪些状态能从输出重构 | 删掉不可观测的目标 |

用法上的要求：写 `--premise` 时写出那条原理本身（哪个守恒、哪个上界），不要只写「物理」。

## L3 哲学视角

| 算子 | 来源 | 问 |
|---|---|---|
| 现象学：被给予之物 | 胡塞尔 | 对受体而言真正被给予的是什么量？执行器报告的量和受体接收的量是否同一个 |
| 可证伪性 | 波普尔 | 写出一条让想法失败的观测。写不出来就不是可检验的想法（工具据此拒收） |
| 奥卡姆与减法 | 奥卡姆；道家「无为」 | 去掉一个部件、传感器、步骤、参数，系统还能否成立 |
| 范畴检查 | 赖尔 | 被控对象是状态还是过程？目标是量还是关系 |
| 先验条件 | 康德 | X 要可能，必须先成立什么？这些前提能否由系统自己检验 |
| 矛盾与前提改变 | 黑格尔；TRIZ 物理矛盾 | 不折中，改变使矛盾成立的前提 |
| 过程哲学 | 怀特海 | 把「东西」改写为「事件序列」；该用瞬时值还是积分、窗口 |
| 知道与假定 | 认识论 | 哪一步是知道、哪一步是假定；把不可知的时段变为不动作的时段 |
| 约束作资源 | 目的论反转 | 每个约束或故障时刻能否反过来当信息来源 |

这些出处只作为问句的来源，没有逐一核对原著；目录里的问句是工程化的改写。

## L4 社会学视角

| 算子 | 来源 | 问 |
|---|---|---|
| 实践与惯习 | 布迪厄 | 使用者实际会怎么做（清洗、折叠、忽略提示、借用） |
| 问责与信任 | — | 出了事谁负责？责任边界能否做成门禁、许可和可追溯记录 |
| 可见性与规训 | 福柯 | 让哪些内部状态可见，行为会随之改变；可见性会不会引起抵触 |
| 行动者网络 | 拉图尔 | 把非人物件列为行动者，各自的利益与失效方式 |
| 采用与扩散 | 罗杰斯 | 相对优势、兼容性、复杂性、可试用性、可观察性，哪一项阻碍采用 |
| 可及性与不平等 | — | 低成本、低技能、老年、残障版本；哪一步要求专业操作 |
| 规范与法规作输入 | — | 安规、审查红线、隐私法能否反过来成为设计约束 |
| 外部性与公地 | — | 对第三方的影响能否内部化 |
| 社会建构的判据 | 社会建构论 | 什么算「安全/有效」是协商出来的；判据能否参数化 |

对专利撰写尤其有用的是「规范作输入」（例如只用非治疗目的的量）和「问责」（许可位、不可绕过的联锁），它们直接产生权利要求里的限定。

## L5 跨域类比

结构同构（方程形式相同的另一领域）、生物类比（只取可实现的机制，不取比喻）、历史先例（旧技术如何解决同一问题，以及当年为何失败）。

## 一条想法的完整登记

```
idea add --title "停机时段标定泵效率" --operator L2.conservation   --premise "流量收支中用户用水一项不可观测；夜间停用时该项为零"   --claim "把夜间停用时段当作标定窗口，用已知功率的短脉冲标定本季泵效率"   --falsifier "停用时段标定值与台架标定值相差超过重复标定离散范围的 3 倍"
```

`--premise` 写原理，`--claim` 写想法，`--falsifier` 写能推翻它的观测。三者缺一，登记的就不是可演化的想法，而是一句口号。

## 工具怎么「学」

- `idea stats`：按层次和算子统计想法数、进入试验数、采纳数、否决数。几个项目积累之后，这张表会告诉你在这类问题上哪些算子真的出过成果。
- `tick` / 钩子：最近 N 条想法里组合类超过阈值时提醒换视角。
- `idea suggest`：按「最少用过的层次 → 最少用过的算子」确定性轮换，跨至少两个层次；不推荐 L1。

它不给想法打分，不排序，不用模型生成候选。想法的好坏由随后登记的试验说话。
