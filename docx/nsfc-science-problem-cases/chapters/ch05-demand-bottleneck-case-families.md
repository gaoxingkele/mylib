# 第5章：需求牵引·突破瓶颈 — 案例族程序

## Core Idea
需求类最易写成产品标书；凝练程序是**痛点 → 结构障碍 → 1–3 个可检验科学问题**，工程指标只作验收锚，不作问题主语。

## Frameworks Introduced
- **需求抽象三段**：应用窘境（用得贵/用不了/用不好等）→ 结构原因（不确定、规模、多主体、原位不可测）→ 科学问题编号列表
- **瓶颈可击穿性**：每个科学问题必须对应一个可失败的理论/算法/测量断言

## 案例族

### 族J 工程痛点→有限科学问题集（不正常航班型）
| 环节 | 模板 |
|------|------|
| 病句 | 研制国产不正常航班恢复系统，实现民航强国 |
| 病型 | 口号化 + 工程目标冒充科学问题 |
| 改写操作 | 写清窘境结构；拆成预测类+决策类等有限问题；删除“系统研制”作主句 |
| 可检验句 | （1）连锁延误期望的正确快速计算问题：传统方法是否系统性低估？新算法在〔误差/时效〕上可否证伪？ （2）多资源一体化恢复的大规模协同优化：相对序贯局部最优，全局模型可否在〔时限〕内求解至〔质量〕？ |
| 内容映射 | 延误传播模型；规则学习；行列生成等求解器 |
| 创新映射 | 针对谬误的新计算；融合优化+学习的恢复算法（不是“上线系统”） |

### 族K 卡脖子测量/保真（深地保真、GNSS 质量、海洋信道等）
| 环节 | 模板 |
|------|------|
| 病句 | 突破深地/深海关键装备国产化 |
| 病型 | 技术堆砌；未知量未命名 |
| 改写操作 | 问“保/测什么、在何约束下原理是否成立” |
| 可检验句 | 在〔极端赋存环境〕下，〔状态量集合〕的原位保持与原位测试原理是什么？无〔某保真维度〕时参数偏差的主导机制为何？ |
| 内容映射 | 原理；控制/密封/估计方法；率定与不确定度 |
| 创新映射 | 原理层构想（如“五保”）+ 使原理可执行的方法（装备是载体） |

### 族L 产业瓶颈中的机制核（涂层界面、封装应力、迁移率、果形调控等）
| 环节 | 模板 |
|------|------|
| 病句 | 解决〔器件/作物〕性能提升与可靠性问题 |
| 病型 | 过宽；不可证伪 |
| 改写操作 | 性能差距 → 候选机制竞争 → 单一可判决机制问 |
| 可检验句 | 〔失效/低效〕是否由〔界面相容性/多场耦合应力/缺陷态〕主导？在〔工艺窗口〕内调控〔变量〕能否按机制预期改善〔指标〕？ |
| 内容映射 | 机制解析实验；模型；定向调控验证 |
| 创新映射 | 机制结论 + 由此导出的增强/相容方法 |

### 族M 公共服务/健康管理瓶颈（慢性病、多灾种风险等）
| 环节 | 模板 |
|------|------|
| 病句 | 构建智慧健康管理平台赋能慢病防控 |
| 病型 | 平台口号；无科学断言 |
| 改写操作 | 个性化决策中的未知：筛查阈值、预测可识别性、干预可控性 |
| 可检验句 | 在〔数据与伦理约束〕下，个体风险的可预测上限与最优筛查策略是什么？控制策略对〔结局〕的因果效应如何识别？ |
| 内容映射 | 模型可识别性；策略优化；验证队列 |
| 创新映射 | 可检验的策略理论，而非 App 功能列表 |

## Mental Models
- Use **“用得贵/用不了/用不好”清单** when 诊断真需求 vs 假爱国叙事
- Prefer **两个关键科学问题** over 一个巨型“综合集成问题”
- Think of **应用成功** as 对科学问题的强检验，不是问题的替代表述

## Anti-patterns
- **技术堆砌**：列出 5 种算法/芯片/材料却无主未知
- **卡脖子修辞过剩**：段落全是战略语，零可证伪句
- **把指标当问题**：“将延误恢复时间缩短至 30 分钟”是目标，不是科学问题

## Worked Example
**病句**：针对航班延误开展智能运维与数字化转型。  
**抽象**：成因不确定 + 规模巨大 → 必须精准预测与高质量决策。  
**问题集**：(1) 连锁延误期望计算谬误如何纠正？(2) 多资源协同模型如何在时限内求到可用解？  
**映射**：内容=传播计算+规则库+行列生成；创新=三方法；系统上线=意义/检验。

## Key Takeaways
1. 需求类质量取决于抽提深度，不取决于痛点形容词强度。
2. 科学问题宜少而硬，通常 1–3 个。
3. 装备/系统/平台是载体与检验场。
