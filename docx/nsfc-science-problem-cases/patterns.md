# 模式与可执行模板

## Pattern: 属性锚定后写句
**When to use**: 选题或多属性摇摆  
**How**: 选 1 主属性 → 用该属性判据写主问题句 → 检查内容/创新不漂移到其他属性话术  
**Trade-offs**: 次属性可在意义段轻点；正文双属性并重易失焦

## Pattern: 四段式压缩故事
**When to use**: 用户只给项目故事或成果罗列  
**How**: 强制输出四段各 2–4 句；段1末必须出现凝练后的问题句；段2只写可击穿困难  
**Trade-offs**: 会丢掉人物情节；换来可审核结构

## Pattern: 无穷追问收敛
**When to use**: 问题过大（宇宙/肿瘤/意识级）  
**How**: 列出问号链 → 标出可观测最弱环 → 主问=该环；其余降为子问或删除  
**Trade-offs**: 看似“格局变小”，实为可做

## Pattern: 需求升维两步
**When to use**: 本子像产品标书  
**How**: (1) 窘境结构三句话 (2) 产出 ≤3 个科学问题，每个带判据；系统/装备改称载体  
**Trade-offs**: 产业话术变少，函评科学性上升

## Pattern: 分叉显式化
**When to use**: 聚焦前沿类  
**How**: 一句写主流路径，一句写结构性困境，一句写你的分叉与检验场  
**Trade-offs**: 需承认热点拥挤

## Pattern: 接口命名交叉
**When to use**: 共性导向/交叉  
**How**: 先命名接口量 → 再写两边如何通过它对话 → 最后给迁移测试  
**Trade-offs**: 无接口则建议改回单域问题

## Pattern: 病句七步改写
**When to use**: 任意问题初稿  
**How**: 诊病型 → 钉未知 → 补边界 → 嵌观测量 → 写对照 → 工程降维 → 单主问  
**Trade-offs**: 首轮句子变“丑”但可审；再润色

## Pattern: 病句类型速查表
| 病句类型 | 例子特征 | 操作 |
|---|---|---|
| 技术堆砌 | 开发/优化/集成/基于A+B+C | 追问未知量与可测参量 |
| 口号化 | 四个面向/赋能排比 | 删口号，留一个可指认瓶颈 |
| 不可证伪 | 深入探讨、全面揭示 | 改成若P则观测Q |
| 工程冒充 | 研制系统/建成平台 | 升维到原理/算法，载体降级 |
| 过大无主轴 | 全能系统全链条 | 切到主导尺度一个矛盾 |
| 属性漂移 | 四类都沾边 | 强制主属性 + 一句辩护 |

## 句式骨架（槽位可替换）

1. `在〔边界条件〕下，〔对象〕的〔现象〕由〔H1〕还是〔H2〕主导？可用〔测量〕区分。`
2. `〔断言S〕在〔尺度/约束〕是否仍然成立？若否，〔状态〕的定量判据是什么？`
3. `〔工程失败模式〕的根子是〔不可测/不可建模环节〕；科学问题是〔原理/算法〕。`
4. `相对〔主流路径〕，在〔困境〕下采用〔分叉〕，能否在〔检验场〕上同时满足〔约束组〕？`
5. `〔域A〕与〔域B〕通过〔接口量〕如何建立对应，并使〔优化/调控〕不破坏〔本质结构〕？`
6. `〔意外现象〕是否可归因于〔机制M〕？在〔对照〕下可否重复并推广到〔类〕？`
7. `针对{瓶颈/反常}，现有认识停留在{层级}；关键科学问题为：{可检验问题句}。归属{单一属性}，因为{一句辩护}。`

## 审查清单（提交前）
- [ ] 主问题句可读且可失败  
- [ ] 无技术堆砌/口号化/工程冒充残骸  
- [ ] 属性、问题、内容、创新同轴  
- [ ] 创新击穿已陈述困难  
- [ ] 应用指标未占据问题主语
