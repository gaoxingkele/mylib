# Patterns · 案例→程序

## 病句类型 → 改写操作
| 病句类型 | 例子特征 | 操作 |
|---|---|---|
| 技术堆砌 | 开发/优化/集成… | 追问控制机制与可测结构参量 |
| 口号化 | 四个面向排比 | 删口号，留一个可指认瓶颈 |
| 不可证伪 | 深入探讨、重要意义 | 改成若P则观测Q的假说句 |
| 过大 | 全能系统全链条 | 切到主导尺度一个矛盾 |
| 属性漂移 | 四类都沾边 | 强制主属性 + 一句辩护 |

## 追问迭代模板（原创向）
Q1 观察到什么反常？ → Q2 现有理论何处不够？ → Q3 最小可检验命题？ → Q4 关键实验/观测是什么？

## 需求抽象模板（瓶颈向）
技术瓶颈陈述 → 拆成保真/测量/控制等技术子问题 → 每一子问题下的科学问题（机制） → 选源头问题作为关键科学问题。

## 交叉融通模板
领域A表述 + 领域B表述 → 对齐到同一组变量 → 写出共性机制句 → 声明各自独特约束。

## 输出句式（可直接进本子）
> 针对{瓶颈/反常}，现有认识停留在{层级}；本项目凝练关键科学问题为：{可检验问题句}。该问题归属于{单一属性}，因为{一句辩护}。
