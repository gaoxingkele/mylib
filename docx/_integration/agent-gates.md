# Agent 执行门禁（两本 AI 写作书 → agent 视角改写）

两本源书（《论文不是写出来的》《如何用AI写论文》）是写给“使用 AI 的人”看的：
“人工回源”“AI 是实习生”“作者签字”。当执行者本身就是 agent 时，这些规则分成两类：

- **A 类：agent 必须自己执行并留下证据**的检查；
- **H 类：agent 不能代替作者完成**的事项——不得假装已完成，必须在交付物末尾列成“待作者确认”清单。

每次起草、改写、评审一段学术或申报文本，按 G1→G7 顺序执行。任何一项不通过，就不能交付，或者在交付物中显式标注。

| # | 门禁 | 类型 | agent 怎么做 | 通过条件 | 源书出处 |
|---|---|---|---|---|---|
| G1 | 场景与规则 | A+H | 先确认文本用途（期刊/学位/基金/商业申报）和管理主体规则；查不到就写“规则未核实” | 交付物写明适用规则或“未核实” | 规范 ch02 自证第 1 步、ch05 |
| G2 | 资料投喂优先 | A | 综述、相关工作、事实句只用：用户给的材料、检索工具返回的条目、仓库内已核实文件。**禁止**凭记忆生成参考文献 | 每条引用都能指出来源（文件路径/检索结果/DOI） | 思维 ch02 资料投喂法；规范 ch04“不可直接生成假文献” |
| G3 | 主张—证据绑定 | A | 每个事实主张同句或邻句给出证据；没有证据的改成【待补：所需材料】，不得改写成模糊说法掩盖 | 无证据主张数 = 0（【待补】不算） | 两书句级硬约束 |
| G4 | 分步与可回滚 | A | 长文按“框架→字数分配→分窗起草→跨窗术语表→合并”推进，每步保留中间产物 | 中间产物存在，可以单独复核 | 思维 ch07 防黑箱、ch08 倒金字塔 |
| G5 | 创新与问题可检验 | A | 创新句必须落到“既有理论 T 在情境 S 下预期 R，观测 O 与 R 冲突，故引入 C 并用 M 检验”；每条矛盾或缺口锚定 ≥2 篇已核实文献，不足则标【待补】 | 无“首次/填补空白”式空创新句 | 思维 ch05 负面启发 |
| G6 | 结构指标 | A | 运行 `scripts/zh_structure_lint.py check`；改写前后运行 `compare`；然后运行 `academic-humanizer` 的 `deai.py check` 看词句级命中 | lint 无新增超阈项；humanizer gate 通过 | 规范 ch04“AI 味=约束不足”；本仓库校准 |
| G7 | 留痕与披露 | A+H | 记录工具/模型名、提示要点、生成与人工修改范围；是否需要声明由 H 类确认 | 交付物附使用记录；声明措辞列入待确认 | 规范 ch02 自证第 5–6 步、ch05 |

## H 类：必须交还作者的事项（照抄进交付物末尾）

```
待作者确认：
1. 适用的 AI 使用规则（学校/期刊/资助方）及是否需要声明：____
2. 以下引用已由 agent 回源，仍需作者通读确认观点未被曲解：____
3. 以下【待补】需要作者提供真实材料，agent 未编造：____
4. 创新点与假说是否代表作者本人的研究判断：____
5. 署名与责任：AI 不列为作者，文责由作者承担
```

## 禁止项（任何模式下都不做）

- 生成“看起来真实”的参考文献、数据、预实验、客户、订单或证书；
- 为了降低 AIGC 检测分数做同义替换、加错别字、加口语噪声；
- 把 H 类事项写成“已确认”“已审核”。
