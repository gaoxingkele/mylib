# 从工程与技术需求凝练选题

## 程序
1. 进入生产/社会一线，记录可重复现象（察标求本）。
2. 把对象视为系统：结构、边界、环境、动力、演化阶段。
3. 将现象归类为：结构类 / 环境类 / 演化机理类 / 模型类 / 方法类 / 调控原理类。
4. 抽象科学问题（去掉品牌、工况口号，保留机制变量）。
5. 映射到基金类型：机理类或模型类为主干。

## 句式骨架
> 工程上表现为{故障/瓶颈}；系统分析表明关键在{结构或环境要素}于{演化阶段}的{响应}；故凝练科学问题为：阐明{A}如何通过{路径}决定{B}。

## 反模式
直接把工程任务书改名为科学问题；只有需求叙事没有机制变量；演化阶段不声明导致机理错位。
