# Chapter 13: 循环嵌套 · 系统修改 · 函评问题

## Core Idea
本子是系统工程：大循环套小循环，改到自洽；函评高频问题多半是「技术主语 / 无假说 / 不呼应 / AI 空转」。

## Frameworks Introduced
- **循环嵌套修改序**（书中操作路径）：
  1. 先内容与目标 → 2. 立项依据 → 3. 凝练科学问题 → 4. 方案 → 5. 可行性/基础/创新 → 6. 计划 → 7. 摘要回检 → 全程反复。
- **字词—句段—篇章尺度**：词准（科学词汇）→ 句段有脉络 → 篇呈多尺度科学问题。
- **主线 vs 辅助**：背景/假说/目标/内容/方案/路线/预期=主线；关键问题/关键技术/可行性/创新等=凝练辅助，忌摘抄重复；计划/条件/基础须实事求是。
- **科学 vs 技术描述分工**：前半科学；内容方案偏实现但仍为科学问题服务。

## Key Concepts（高频函评语义）
- 「科学问题与技术问题混淆」= 把科学简化成技术指标，缺原理机制。
- 「缺少宏观一招鲜」= 无创新思想/结构/理论/应用抓手。
- 「领域大问题当自己的问题」= 不切青基/面上体量。
- 「科学问题与创新性混淆」= 问题是本质；创新多指解决问题的方法（若本质本身新，二者可重合）。

## Anti-patterns / 书中常见问题清单（执行时逐条勾销）
1. 科学问题凝练不够（未到物理化学过程/构效）。
2. 创新理解偏差：跟风拼凑。
3. 立项依据第2–3层想当然，缺归纳演绎与假说必要性。
4. 研究内容过技术/工艺；缺计算视角。
5. （结构性）内容条数散、方案重复。
6. 科学问题写成三条工艺。
7. （关联）各部分不呼应。
8. 可行性缺思想/难点分析；名人堆砌。
9. 语言尺度条件实验化；误以为「越分子越好」——关键是**主导尺度关键结构**。
10. **没有科学假说，全靠蒙/做做看**。
11. 摘要喊口号。
12. **AI 写作迹象明显**（下节展开）。
13. 选题不顾平台错位。
14. 题目无方法/问题/目标；乱加「研究」。
15. 文献只会罗列不会脉络化「亮剑」。
16. 图文不并茂或标题不显观点。
17. 可行性写成实验条件/人员条件。
18. 依据—内容—方案—可行性—基础割裂。
19. 开发/研制/工艺词滥现。
20. 为创新而求新，脱离重要科学或工程基础问题。

## AI 常见败笔（专表）
| 败笔 | 表现 | 改写要求 |
|---|---|---|
| 通顺空洞 | 逻辑连接词完美，无机制实体 | 每段必须出现可指称的结构/过程变量 |
| 科学问题外包 | 「请给出本学科科学问题」 | 先写选题目标与干预，再凝练；禁用无定语口号 |
| 方案器械清单 | 只列 SEM/DFT | 写清为何用、测什么量、如何支持/证伪假说 |
| 摘要口号 | 「理论结合实验突破指标」 | 还原问题本质一句+一招鲜+机制落点 |
| 假说缺失 | 优美背景后直接「拟开展研究」 | 补「干预→预期演化→检验」 |
| 创新贴标签 | 「具有重要创新性」 | 归入四类创新并绑定一招鲜 |
| 跨学科错位 | AI 按学院推荐问题 | 用漂移规则按目标重定母语 |

## Sentence Skeletons（函评对症）

### 回应「太技术」
- `将原表述「优化[指标]」改写为「阐明[主导结构]如何决定[指标对应的理化过程]，并以[一招鲜]检验该决定关系」。`

### 回应「无假说」
- `假说：在[边界]下，[干预]使[结构变量]沿[方向]变化，导致[过程R]速率/路径改变；若[关键观测]不出现，则假说不成立。`

### 回应「不凝练」
- `领域瓶颈[大]在本项目收敛为[小而深的主导环节]；定语=[体系+干预]。`

## Worked Example（修改策略）
函评「思想有独特性但未突出与现有区别」→ 不换思想，重写：五问第3–5层、创新栏、摘要思路句、路线视觉强调——处处显差，不指望评审挖掘。

## Key Takeaways
1. 先系统自洽，再抠字；摘要最后关闸。
2. 假说与一招鲜是抗函评双核。
3. AI 可用作文献归类助手，不可作科学问题发包方。
4. 修炼内功：问题认知+年度硬论文/会议，大于打听消息。
