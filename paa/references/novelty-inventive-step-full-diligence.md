## 一、现有技术核验必须"两条腿"，NPL 不是可选项

**专利腿**：incoPat（法定，账号恢复前用 `google-patents-search` skill 免费兜底）。
**NPL腿**：`paa/skills/npl-prior-art-search/` 路由（已建好，之前的诊断流程没调用，这是执行缺口不是能力缺口）——
算法/软件类发明默认走 `paper_search`（arXiv/S2/OpenAlex 快速并发初扫），中文场景叠加 `academic-search`，
"该领域是否已被论文公开"这类全面性问题用 `paper-search-pro` 四档深扫。

**两条腿都要跑，且都要跑够以下四类检索目标**（revised 报告示范的完整覆盖面）：

1. **D1 最接近现有技术**：技术领域+技术问题+技术效果+公开特征数量综合最接近的单篇（专利或论文均可）；
2. **D2/D3... 逐特征惯用手段佐证**：对独权里**每一个**声称的区别技术特征，单独去搜"这个特征本身是不是某个成熟范式的标准做法"——不是为了推翻D1，是为了在三步法第三步时诚实回答"这条区别特征本领域技术人员是否容易想到"；
3. **结合启示佐证**：专门检索"能把D1和D2联系起来的教科书/综述/工程实践文献"，因为审查员判显而易见性时问的正是"现有技术中是否存在启示将二者结合"，只证明D1、D2各自存在不够；
4. **同族与法律状态**（incoPat 恢复后）：避免漏掉更早公开的同族成员，确认候选对比文件当前法律状态。
5. **申请人/发明人自身在先公开**（交底书源自论文、学位论文、项目报告、预印本、会议报告的案件必做）：
   - 检索口径用"作者姓名 + 单位 + 核心机制的英文范式名"，**不得只用论文精确题名**——论文从投稿到发表题名常有变化，精确题名检索会因此系统性漏检（真实教训：某案交底书本地稿题名与已发表版本题名不同，仅8个词的措辞差异，精确题名核验判"未发现"，实际早已公开，后期被迫整体重构）；
   - 覆盖期刊在线优先版、arXiv/SSRN/ResearchGate/机构知识库、会议论文集与报告幻灯片、学位论文库；
   - 结论三选一并写明依据：**已公开（公开日 YYYY-MM-DD + 出处）/ 经核验未公开（渠道 + 核验日期）/ 不确定**。每次独权实质修改后、每次对外交付前各重新核验一次，过期结论不得沿用；
   - 撰写分支必须与结论一致：**已公开** → 按现有技术引用，独权重心移到论文未公开的特征；**经核验未公开** → 背景技术不得把该论文写成现有技术（避免自认现有技术），并提示申请人先申请、后发表；**不确定** → 按已公开来设计权利要求，但背景技术是否引用由代理人决定，在报告中列为人工待决项；
   - 宽限期只适用于专利法第二十四条的四种法定情形（国家出现紧急状态或非常情况时为公共利益目的首次公开；在中国政府主办或承认的国际展览会上首次展出；在规定的学术会议或技术会议上首次发表；他人未经申请人同意泄露其内容）。普通期刊发表和预印本不适用；是否适用由代理人判断。

## 二、检索对象的选词纪律：不要只在专利数据库的语言里想问题

revised 报告能找到 1987 年的生产排程论文，是因为检索时把本发明的核心机制**翻译成了工程学的通用范式名称**
（"冻结+局部重装" → "frozen horizon rolling schedule"），而不是停留在"电力培训考核任务生成"这个专利叙述层面的措辞。
**检索前必须做一次"范式翻译"**：把发明要素表里的每个核心机制，用計算机科学/运筹学/控制论/分布式系统/密码学等相邻学科的**标准术语**重新表述一遍，再拿这些标准术语去检索，而不是只用专利申请里的原创措辞去检索（原创措辞本来就是为了显得"新"而起的，用它检索反而检索不到真正的公知范式）。

常见范式对照表（持续补充）：

| 专利里的说法 | 可能对应的学科标准范式 |
|---|---|
| "冻结未受影响的对象、仅对受影响对象局部重算/重装" | 生产排程"frozen horizon rolling schedule"；增量计算"incremental recompute"/"dependency-driven re-evaluation"；数据库"materialized view incremental refresh" |
| "多方/多会话结果加权聚合出一个可信结果" | 多智能体系统"credibility/trust scoring"；联邦学习"client weighting"；分布式共识"Byzantine fault tolerance"/"weighted voting" |
| "版本号/时间戳比较后决定谁覆盖谁" | 数据库"optimistic concurrency control (OCC) / compare-and-swap (CAS)"；分布式系统"vector clock"/"last-writer-wins" |
| "多状态互斥优先级决定处理路径" | 状态机/工作流引擎的标准优先级仲裁模式 |
| "安全关键判定不能用缓存/历史结果代替实时数据" | 安全关键系统设计准则（不可信任缓存做安全门禁），本身也是已知工程原则，但**领域组合后的具体修复点**可以是创造性锚点（见下节） |

## 三、算法设计与专利原理的贴合审查（提高创造性论证的核心动作）

对说明书算法章的**每一个**公式/判定逻辑，按以下四步走，不是走完形式就行，每一步都要给出具体结论：

1. **范式识别**：按上表（或自行判断）确定这个算法模块对应哪个相邻学科的标准范式，写明范式名称与出处类型（不要求找到具体文献，先识别范式类别）；
2. **失败模式推演**：假设把这个标准范式原封不动搬到本专利的具体场景里，会在哪个具体环节出错？（这一步就是`退化机制反例推演`已经在做的事，但要求专门针对"跨领域迁移"这个角度重做一遍，不是只考虑"删掉某个限定"）
3. **锚点核对**：本发明现有的权利要求限定里，是否存在**精准对应第2步失败模式**的具体限定？
   - 如果存在——这条限定就是真正的创造性锚点，应该在说明书"与现有技术的区别"里正面点出"这是解决XX范式跨领域迁移到YY场景时会产生的ZZ问题"，而不是泛泛写"结合产生了协同效果"；
   - 如果不存在——说明当前独权的创造性论证是空的，要么补一条精准修复失败模式的限定，要么放弃把这个模块当创造性核心，改找别的区别特征；
4. **NPL反向核验**：拿第1步识别出的范式名称去 NPL 检索一遍，找该范式领域内是否已有人处理过第2步的失败模式——如果已经有人处理过，说明本发明的"修复"本身也不新，创造性锚点需要进一步收窄到"在电力/本领域这个具体约束下的修复方式"。

**这一步最好在撰写阶段就做**（写完说明书草稿后，收窄/答辩前必须补做），而不是等审查员或无效请求人指出来才做——P06-3 revised 报告能给出③"现场门禁不可被冻结替代"这条有效的创造性补强建议，正是因为做了这四步；我们自己撰写时如果先做这四步，能在提交前就把这条限定写清楚，而不是事后被动补救。

## 四、区分"充分公开型补充"与"创造性型补充"，不要混淆

任何一条打算加进说明书/权利要求的补充内容，先分类：

- **充分公开型**（阈值取值范围、内部公式的具体系数、初始化规则）——只解决26.3，**跟22.3无关**，补了不会让创造性变强，不补会被26.3打回，两者是独立的门禁，不要指望26.3补充能顺带解决创造性问题；
- **创造性型**（第三节第2-3步找到的、精准修复某个跨领域迁移失败模式的限定）——这才是应该重点撰写、重点在"与现有技术的区别"里正面论证的内容；
- **中性甚至负面型**（把内部实现细节用公式形式写出来，但这个公式本身是教科书级常见算法，如EWMA/指数衰减/CAS）——补充后**审查员反而可能拿它当"每个环节都是惯用手段"的又一个例证**，补充前要想清楚这条是不是在给对方递刀子。

## 五、授权概率的表达方式：跟着走，而不是只看总分

revised 报告用的是"CNIPA X%~Y%"区间+"较上一轮变化"这种表达，比单纯的0-100分制更贴近审查员的真实决策心理（审查员不是在打分，是在决定"驳回/授权"这个二元结果，区间概率比连续分数更诚实地表达了不确定性）。以后除了 Jev 门禁分数和四角色评分，**每次重大修订后也应该给出一个"CNIPA授权概率区间+相比上一轮的变化方向和原因"的一句话结论**，比如"新颖性大概率过，创造性风险中等偏高，本次补充未改变该判断"——这比单独报四个数字更有决策价值。
