# 来源路由（Source Routing）

使用实际可用的最高置信度通道，并区分行业聚合、行业样本和逐玩家证据。

## mylib 默认优先顺序

1. [`patsnap-search`](../../patsnap-search/SKILL.md) / [`incopat-search`](../../incopat-search/SKILL.md)：行业检索、申请人/受让人证据、代表专利取件。
2. 智慧芽论文接口与 [`npl-prior-art-search`](../../npl-prior-art-search/SKILL.md)：论文、机构和引用证据。
3. [`google-patents-search`](../../google-patents-search/SKILL.md)：结构化通道不可用或需独立复检索时使用。
4. 领域专属学术、申报数据库，以及可用的 `Exa`、`Tavily`、`Brave`、通用 web 和已知 URL 阅读器。

## 按信息需求路由

| 需求 | 首选通道 | 降级通道 |
| --- | --- | --- |
| 候选玩家发现 | 智慧芽 / incoPat 行业检索 + 官方/实时网络来源 | Google Patents + 通用 web，披露玩家发现损失 |
| 逐玩家技术证据 | 按玩家独立检索并深读取件后的代表专利 | 独立复检索 + 官方技术资料；不得用行业样本替代 |
| 论文与机构归属 | 智慧芽论文接口 + NPL 路由 | 学术数据库或通用 web |
| 上市公司披露 | 官方申报或财务数据库 | 官方域名 web |
| 产品、发布及公开信号 | 官方页面和实时检索 | 通用 web + 已知 URL 阅读器 |

## 原文与降级规则

- 专利全范围计数和路线广度来自聚合而非样本；代表专利进入正式技术画像前必须取原文，搜索摘要只作候选。
- 行业样本、玩家样本和玩家全量聚合分别记录；重要排名尽量跨独立来源复核，不把“未检出”写成“不存在”。
- 若结构化检索不可用，在 `method_decisions.md` 说明实际通道和覆盖损失，降低玩家完整性、排名和路线广度主张的置信度。
- 除非证据真正支持，否则不得将采样或降级运行呈现为完整市场图谱；空白机会也不能直接转化为可专利性或 FTO 结论。
