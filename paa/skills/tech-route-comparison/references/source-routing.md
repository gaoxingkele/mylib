# 来源路由

使用实际可用的最高置信度通道，并在归一化前保持各路线证据独立。

## mylib 默认优先顺序

1. [`patsnap-search`](../../patsnap-search/SKILL.md) / [`incopat-search`](../../incopat-search/SKILL.md)：按路线检索专利并取代表专利原文。
2. 智慧芽论文接口与 [`npl-prior-art-search`](../../npl-prior-art-search/SKILL.md)：前沿论文、DOI 和引用证据。
3. [`google-patents-search`](../../google-patents-search/SKILL.md)：结构化通道不可用或需要独立复检索时使用。
4. 领域专属学术、标准数据库，以及可用的 `Exa`、`Tavily`、`Brave`、通用 web 和已知 URL 阅读器。

## 按信息需求路由

| 需求 | 首选通道 | 降级通道 |
| --- | --- | --- |
| 路线定义与候选证据 | 智慧芽 / incoPat 按路线独立检索 | Google Patents 独立复检索或通用 web |
| 前沿论文与 DOI 支持 | 智慧芽论文接口 + NPL 路由 | 学术数据库或通用 web |
| 标准、发布及官方公开状态 | 官方来源和实时检索 | 通用 web + 已知 URL 阅读器 |
| 代表专利/论文技术细节 | 对应取件工具取得原文后精读 | 仅摘要时降级为线索，不支撑强对比结论 |

## 原文与降级规则

- 检索列表和摘要只作候选；正式矩阵中的技术判断必须能追溯到原文、官方部署证据或明确标注的开放缺口。
- 各路线使用一致的场景、层级和时间窗口；重要结论尽量跨独立来源复核，“未检出”不等于“不存在”。
- 若结构化检索不可用，在 `method_decisions.md` 说明实际通道和覆盖损失，降低路线广度、新颖性和前沿完整性的置信度。
- 若路线证据明显偏薄，不得将降级运行呈现为详尽分析或确定性排名。
