# Chinese Design Patent Routing

Read this reference only when the protectable subject is product appearance, pattern, color, a GUI, a dynamic GUI, or a partial design. Do not apply invention-claim drafting rules to a design patent.

## Required Inputs

- product name and Locarno-style product category;
- physical product, screen-panel GUI, or GUI-bearing product;
- design points: shape, pattern, color, dynamic transition, or protected portion;
- whether color is claimed;
- whether the application is a partial design;
- whether multiple similar designs are intended for one application;
- actual images or renderable source assets.

No images means the design application is not ready for finalization.

## Deliverables

Design applications use request information, images/photos, and a brief explanation. They do not use invention claims or the five-section invention specification.

- Physical products normally need consistent orthographic views; omit a view only with a supported reason.
- Dynamic GUIs need an initial main view plus enough key frames to uniquely determine the transition.
- Partial designs distinguish the protected portion from unclaimed portions, normally with solid and broken lines, and explain the protected part.
- If color is claimed, use color images and state that color is protected; recognize the resulting scope limitation.
- Multiple similar designs in one application must share the same product and remain within the applicable count and unity rules; otherwise split them.

The brief explanation must state the product name, product use, GUI use when applicable, design points, the representative view, and any necessary color, omitted-view, partial-design, dynamic-process, or basic-design statement. Do not describe internal technical effects.

## Verification

Check view completeness, consistent scale and contours, clean backgrounds, image-to-description consistency, absence of trademarks/model numbers in the product name, and whether the submitted frames uniquely express a dynamic GUI.
