# 评审驱动的申请文件修订工作流（Review-Driven Revision）

来源：zhuanlishenqing 项目电力三案（数字孪生档案校核 / 应急通信召测 / 配电抢修派工）2.4→2.8 的五轮修订（2026-10-10 至 10-13）。本页是通用做法，案件细节留在项目 wiki。

适用：申请文件已有完整 00–07 与 paa 证据包，收到外部评审（网页多模型评审、代理人意见、模拟 OA）后要出下一版；或要回答"分数为什么变、参数够不够、来源算法引没引够"这类问题。

## 0. 三条前提

1. **评审是 judge 级意见**。每条意见先对照 02/03/04/05 原文核实，成立才改；不成立或不宜改的写进修订说明的"不采纳"表并给理由。评审里出现的文献号一律先取件核验再使用。
2. **不为提分改分**。分数变化只能来自文本、证据或检索的真实变化；整改动作只能是评分器定义的六类之一（重新检索 / 重塑创造点 / 补充分公开 / 取得事实证据 / 调整权项 / 停止包装）。
3. **不利结果如实写**。新计算例出现对本案不利的数字时写进说明书并收窄效果主张，不删、不换种子、不换口径。

## 1. 流程

| 步 | 做什么 | 产物 |
|---|---|---|
| 1 | 汇总评审：按案 × 评审端做风险分速查表（注明每端口径：风险↑还是质量↑），提炼"较一致 / 尖锐分歧 / 建议阅读顺序" | `_review_<日期>/汇总.md` |
| 2 | 主代理对照原文初核，写本轮修订规范：通用规则 + 每案 P0/P1 清单（每条：现状 → 改法） | `00_v<X>修订规范.md`（模板见 `templates/`） |
| 3 | 每案一个子代理（并行 ≤3），从工作文件出发执行规范；子代理不出 Word、不提交 git、不改别案、不改技能库、不开浏览器、不写 metaRSI | 工作文件 00–07、paa、`sim/out/v<X>/` |
| 4 | 子代理按规范回报（≤40 行）：采纳/不采纳统计、权 1 逐条改动、从权编号映射、新增技术内容、新计算例数字（含不利）、核验结果、validate、AHP 对比、遗留 | 回报 |
| 5 | 主代理核对：快照与工作文件哈希一致、四门禁、评分非 stale、02–05 禁词与借词扫描为 0 | 核对记录 |
| 6 | 统一出 Word（`paa/scripts/build_cnipa_docx.py`），检查无残留 LaTeX、章节与图片齐全 | `*_完整申请文件_v<X>_CNIPA版式.docx` |
| 7 | 评分汇总追加本版节；metaRSI 记 trial / negative / signal；git 提交 | 汇总、账本、提交 |

## 2. 三种修订规范

- **按评审修改**（`templates/review_fix_spec.md`）：先核验新对比文件 → 先补执行逻辑与清楚性缺口 → 再按多数评审的退守组合把从权并入独权（机制展开式，不搬公式）→ 第 33 条意识（未递交可补入，但标"新增技术内容"）→ 复跑受影响计算例 → 快照 + 修订说明 + 重评。
- **叙事链闭合**（`templates/narrative_closure_spec.md`）：技术问题 → 原理 → 机制 → 效果统一到一条链上。四条规则：每条效果对应计算例数字；每个区别特征用它真正改变的指标衡量；效果的适用前提写进有益效果段；标题措辞须在权 1 出现。再以新权 1 为对象做三通道 + NPL 全文查新。
- **查新重评 + 三问**（`templates/search_rescore_spec.md`）：全文查新 → 分数逐准则分析与整改动作 → 参数来源审计与公开数据补证 → 来源论文部件审计（必要 / 有益 / 不必要 / 不可引入）→ 重评。

## 3. 三个被反复验证的取证手法

1. **最接近现有技术基线对照**：按对比文件原文（权 1、关键段落）实现其方法，与本方法在同一合成数据、新随机种子上对照。这是创造性 I3/I4 的事实证据，比改写三步法文字有用；对基线有利的结果也要写。
2. **机制因果链量化**：按 `patent-grant-scorer/references/mechanism-convergence-review.md` 第 7 节，写出"前一机制改变了后一机制的哪个输入 / 状态 / 允许动作"，每一步给数（区间宽度、覆盖率、窗口数、决策改变比例）。
3. **参数来源审计**：扫出说明书与仿真参数表里标注"无文献依据 / 待实测 / 取自摘要 / 假设"的项，按 标准 → 同行评审论文 → 公开数据集 → 官方统计 → 厂商规格 的顺序补证，来源取件核验后才写入；补不到的明确"需实测"。

## 4. 子代理纪律（写进每份规范）

- 并行 ≤3；每案只动本案目录。
- 重启自己的脚本只按自己记录的 PID 终止，**禁止按进程名终止**（`taskkill /IM python.exe`、`Stop-Process -Name`）——2026-10-12 曾误杀用户两个无关长期进程。
- 不编造文献号；权利要求禁"约/大概/左右"；全文禁"100%/大幅/领先/显著"；02–05 不写脚本名、版本标记、"评审/GPT/模型"字样、来源领域术语。
- 新计算例用新随机种子，不复用已评估的 seed；不读 metaRSI 保留窗口。
- 改权 1 后：从权重编号、说明书引用、04 流程图、05 摘要、06/07、paa 同步；claim_hash 重绑后重评，非 stale。

## 5. 证据等级提示

评审意见 = judge；新种子合成仿真 = in_sample；先登记影子规则再在留出窗口计分 = prospective。AHP 指数是内部就绪度指数，不是授权率；incoPat 未执行时证据置信度封顶。
