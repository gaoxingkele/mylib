# v<X> 修订规范模板：叙事链闭合 + 全文查新 + 重评（narrative_closure）

> 用法：计算例证明"效果写得比前提强"或"效果重心与标题、区别特征对不上"时用本模板。每案一个子代理。

## 1. 升级目标：让"技术问题 → 原理 → 机制 → 效果"闭合

把每案的**技术问题、独权押点、有益效果、计算例指标**统一到同一条链上。通用要求：

1. 有益效果的每一条都要能在说明书里找到对应的计算例数字或推导；没有数据支撑的效果改为"预期"口径或删除。
2. 每个区别特征都用**它真正改变的指标**衡量，不用无关的总指标（例：安全联锁用"到场后才发现带电通路次数 / 往返次数 / 开工等待"衡量，不用总停电户时；选测策略用"达阈值所需接入次数"衡量，不用全流程正确率）。
3. 效果的适用前提写进有益效果段（例："在其余户表归属正确的前提下"；"只在资源稀缺时起作用"）。
4. 标题中的措辞须在权 1 中出现或有明确定义；标题、技术问题、独权前序三者口径一致。
5. 发明内容"与最接近现有技术相比"段按新权 1 重写；最接近现有技术按核验后的文献重新选定（可能已变）。
6. 说明书新增段落：段号连续，00/01/04/06/07/paa 的段落引用同步。

各案任务说明：<断点在哪（原文位置）→ 要统一成什么 → 新指标是什么>。

## 2. 计算例

- 新指标用批次公共仿真器或案内 `sim/` 现有脚本扩展；参数仍取已核验的论文 / 标准证据，不新造参数。
- 结果写"计算例（合成/仿真数据，非实测）"；不利结果如实写。
- 不读 metaRSI 保留窗口；新指标用新随机种子（不复用已评估的 seed 集作验证）。

## 3. 检索：以新权 1 为对象做全文查新（三通道 + NPL）

- 先写 `evidence/search_v<X>/queries.md`：按新权 1 逐特征和特征组合各出检索式，轴与前几轮不同（权利要求措辞轴、组合轴 A+B、英文同义轴、上位概念轴、CPC 轴），每案 ≥12 条。
- 三通道都跑：`gp_search.py --backend tavily|brave|google "<词>"`；google 直连**每次间隔 ≥30 s**，被拦即停并记录；tavily/brave ≥1.5 s。全部结果存 `evidence/search_v<X>/`（按通道分列）。
- NPL：arXiv `export.arxiv.org/api/query?search_query=all:<≤5 词>&max_results=10`、Crossref `api.crossref.org/works?query.bibliographic=<题名>&rows=3`；只写真实返回的 ID。
- 新候选 `gp_fetch.py --backend tavily`（≥2 s）+ `gp_verify.py` 逐字核验；通过的入 01 定 X/Y/A；取不到的列"未核验线索"。
- 写 `申请书_v<X>/查新报告_v<X>.md`：检索式与通道、命中、新权 1 逐特征对照表、X/Y/A 结论、修改建议。发现 X 类立即停下回报。incoPat 未执行要写明。

## 4. 产物与校验

同 `review_fix_spec.md` 第 4 节；修订说明按"断点 → 改了什么 → 新计算例数字 → 依据"逐条写。

## 5. 回报（≤40 行）

叙事链改动（技术问题 / 权 1 / 效果各怎么改）；新计算例指标与数字；三通道检索条数、新候选、核验结果与定级、有无 X；从权编号映射；validate、AHP；遗留。
