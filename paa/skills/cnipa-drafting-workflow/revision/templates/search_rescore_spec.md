# v<X> 修订规范模板：全文查新重评 + 分数分析 + 参数补证 + 来源部件审计（search_rescore）

> 用法：用户问"再检索评一次 / 分数为什么变 / 参数够不够 / 来源算法引没引够"时用本模板。每案一个子代理；每案在 `申请书_v<X>/分析报告_v<X>.md` 正面回答三问，再决定改不改文本。先读 `patent-grant-scorer/references/mechanism-convergence-review.md`。

## 1. 全文查新（三通道 + NPL，以当前权 1 为对象）

同 `narrative_closure_spec.md` 第 3 节（≥12 式、三通道、NPL ≥4 条、取件核验、查新报告）。

## 2. 分数分析与创造点重塑

- 读上一版与当前 `evidence/scoring/scoring_input*.json`，逐准则列出变动与所引证据；按评分器六类整改（重新检索 / 重塑创造点 / 补充分公开 / 取得事实证据 / 调整权项 / 停止包装）给每个低分准则一条动作。**不为提分改分。**
- 创造性组（I）下降且原因是"构成要素为公知 + 独权收窄"时，整改不是改分，而是：
  (a) 按 mechanism-convergence-review 第 7 节写清"前一机制改变后一机制的输入 / 状态 / 允许动作"的因果链，用计算例给每一步的量化变化；
  (b) **补最接近现有技术基线对照**（新种子）：按对比文件原文实现其方法（及其与第二文件的组合），与本方法在同一合成数据上比较核心指标；结果如实写入说明书计算例与 07 三步法"定量效果"，作为 I3/I4 的事实证据；对基线有利的结果也写；
  (c) 权 1 不再收窄。
- 效果证据组（I4）封顶在"无实测"时，写明哪类实测能解锁，并列为遗留。

## 3. 参数补证

- 扫描 03 说明书与 `sim/` 参数表，列出标注"无文献依据 / 待实测 / 取自摘要 / 假设"的参数，逐个按顺序找公开来源：标准（GB/T、DL/T、Q/GDW、IEC、3GPP、NB/T、RFC）→ 同行评审论文 → 公开数据集 → 官方统计 / 服务承诺 → 厂商公开规格。来源经取件 / Crossref 核验后才写入；写不到的明确"需实测"。
- 产物：`evidence/params/v<X>/参数补证_v<X>.md`（参数 → 原取值 → 来源 → 核验状态 → 新取值 → 是否影响结果）。
- 参数变化影响结果的，复跑受影响的计算例（新种子），数字如实更新；不影响的写明"取值不变、未复跑"。
- 标准条文只有转述、未见原文的要标"转述"，递交前以正式出版物核对。

## 4. 来源算法部件审计

- 列出来源论文 / 交底书文件；逐部件做审计表：
  | 部件（机制名、在来源中的作用） | 本案落点（权项号 / 段落号，或"未引入"） | 判断 |
  判断四档：**必要**（删去则技术问题不能解决或效果不成立）/ **有益**（能补强区别特征或效果，须说明它改变哪一步的输入或状态）/ **不必要**（与场景物理约束无关、纯叠加、或会引入来源领域术语）/ **不可引入**（来源未公开须保密的部分、或与本案独权冲突）。
- 判"有益"且能用计算例证明的，写进说明书（标新增技术内容）并以从权承载；不进权 1，除非它直接补强被评审点名的区别特征。
- 禁止把来源领域术语带入 02–05，只写本案功能定义术语；团队未公开论文不作现有技术，不入 01。
- 00 发明要素表须有来源记录（来源文件、所用部件、不作现有技术的声明）。

## 5. AHP 重评与产物

- 更新 `scoring_input.json`（claim_hash、search_input 绑定本轮检索、证据引用更新；新基线与新参数作为证据引用），`ahp_only_scorer.py` 出 `scoring_result_v<X>.json`，非 stale，复制为 `scoring_result.json`。
- 文本若改动：工作文件、大纲、paa 同步；validate PASS；快照 `申请书_v<X>/`（含查新报告、分析报告、修订说明）。文本未改动的案也建快照目录放查新报告与分析报告，修订说明写"文本未变"。
- 不做：Word、git、改别案、改技能库、浏览器、BigQuery、metaRSI；重启脚本只杀自己的 PID。

## 6. 回报（≤45 行）

三通道各命中数、新候选与核验定级、有无 X；三问结论各 ≤6 行；文本改动清单与从权映射；新计算例数字（含不利）；validate、AHP（与上一版对比）；遗留。
