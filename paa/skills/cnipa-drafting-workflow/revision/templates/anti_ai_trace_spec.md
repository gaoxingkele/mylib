# v<X> 修订规范模板：说明书 AI 痕迹与叙事连贯性审查（anti_ai_trace）

> 用法：用户问"有没有 AI 堆砌术语 / AI 痕迹过重 / 段落逻辑是否完整 / 前后是否呼应递进"时用本模板。每案一个子代理；先跑 `paa/scripts/check_ai_traces.py` 定位，再人工逐段审读，只改叙事与表述，不改技术内容。

## 1. 原则

- 去 AI 痕迹靠**把文本写成真实的工程叙述**，不靠同义词替换、不靠故意加错别字或口语化、不靠堆砌"人味"套话。
- 不改权利要求；不改数值、公式、符号、附图标号、段号；不新增未经仿真或未经核验的技术内容；不引入来源领域术语；保留所有不利结果与限制。
- 说明书叙述的读者是审查员：每段要让人看得出"为什么这么做"，而不是只看到"做了什么"。

## 2. 检查清单（脚本定位 + 人工判断）

| 类别 | 症状 | 处理 |
|---|---|---|
| A 套话 | "值得注意的是 / 综上所述 / 赋能 / 闭环 / 显著提升"等过渡与拔高词 | 删除或改为具体事实 |
| B 术语堆砌 | 一段内连续新造 ≥3 个定义术语；新造术语只用一次、不入权利要求 | 能用已有技术词描述的不另造词；一词一义，首次使用处定义，其后不换说法 |
| C 句式模板 | 同一句首重复 ≥4 次；逐篇对比文件同模板罗列；句长均匀、节奏平；连接词（因此/从而/进而）过密 | 背景技术按"解决了什么、没解决什么"归并；句长交错，单句 >150 字拆分；连接词只留真实因果处 |
| D 段内叙事 | 技术段只有做法、没有"面对什么具体情形 / 不这样做会怎样 / 得到什么、交给下一步" | 按 情形→理由→做法→落点 补足，理由必须能在已有内容中找到依据 |
| E 首尾呼应 | 技术问题中的子问题在方案、实施例、效果中无对应；权利要求步骤在说明书无展开 | 建立"问题—手段—验证—限制"追踪矩阵（见第 3 节），缺口处补一句对应或在限制中承认 |
| F 递进 | 段与段之间互不相接；术语先用后定义；实施例与发明内容顺序不一致 | 上段落点作下段起点；每节开头回扣其对应的子问题，结尾指明交给哪一节；先定义后使用 |

## 3. 追踪矩阵（必须产出）

`anti_ai/追踪矩阵_v<X>.md`：列 = 子问题（取自"技术问题"段，逐条编号）｜解决手段（权项号 + 段号）｜验证（计算例段号 + 指标）｜限制或不利残留（段号）。任一格为空，要么补一句对应，要么如实写"未验证"。

## 4. 产出与校验

- 改前改后各跑一次 `check_ai_traces.py`，把指标前后对比写入 `anti_ai/反AI痕迹审查_v<X>.md`；列出逐段修改清单（段号｜症状类别｜改法）。
- 校验：02、04、05 逐字节不变；03 中所有数字、公式、标号、段号集合与改前相同（用脚本比对数字与标号集合）；禁词扫描；validate 四门禁 PASS；AHP 重评（claim_hash 不变时分数不动）。
- 快照 `申请书_v<X>/`（含 `修订说明`、`anti_ai/`）；不做 Word、git、改别案、改技能库、浏览器、metaRSI。

## 5. 回报（≤30 行）

改前改后指标；修改段数按类别；追踪矩阵中的缺口数与处理；仍无法消除的模板化来源（如法定格式）；校验结果。
