# CNIPA 2026 Drafting Checklist

本清单用于写前、写中、提交前自检。命中严重项时，应回到对应 agent 修改，不得直接合稿。

## 1. 文件结构

- [ ] 请求书信息、说明书摘要、摘要附图、权利要求书、说明书、说明书附图齐备。
- [ ] Markdown / Docx / 图纸版本之间标题、申请名称、附图编号一致。
- [ ] 发明、实用新型、外观设计边界明确；实用新型不写方法权利要求。

## 2. 申请主体与诚信

- [ ] 发明人均为自然人，且对应实质性技术贡献。
- [ ] AI 仅作为辅助起草/整理工具，不列为发明人。
- [ ] 申请人、发明人、共同申请、职务发明归属待确认项有显式标记。
- [ ] 未公开技术材料不得上传到不受控外部服务。

## 3. 权利要求

- [ ] 独权包含解决技术问题所需的全部必要技术特征。
- [ ] 区别特征来自检索报告或用户确认的技术事实，不凭空添加。
- [ ] 从权只引用在前权利要求；不存在多项引用嵌套多项引用。
- [ ] 不出现“如权利要求……所述”。
- [ ] 数值范围、材料、算法参数有来源和说明书支持。
- [ ] 软件/算法类权利要求绑定具体技术对象、硬件交互或数据处理流程。
- [ ] 准备至少一套可用于 OA 的从权合入独权方案。

## 4. 说明书充分公开

- [ ] 技术领域、背景技术、发明内容、附图说明、具体实施方式完整且顺序正确。
- [ ] 每个独权特征在说明书中有明确支持段落。
- [ ] 每个公式字母有中文含义、单位、取值范围或确定方式。
- [ ] 每个算法有流程图、伪代码或足够详细的步骤说明。
- [ ] 每个关键硬件有结构、连接关系、信号/能量/物料流向。
- [ ] 至少一个实施例完整可复现，且不是纯结果描述。
- [ ] 上位概括有多个实施例或等同替换支撑。

## 5. 背景技术与检索

- [ ] 背景技术中的专利号、论文号、公开日均已核验。
- [ ] 若配置 incoPat 等专业中文专利库，已执行深检索并保存原始结果；未配置时已生成查询计划并标记待执行。
- [ ] 每案至少筛出 5-10 件高相关中文专利，并核验著录项、摘要、权利要求 1 和法律状态。
- [ ] 对比文件分级为 X / Y / A 或等价风险等级。
- [ ] 最接近现有技术、共有特征、区别特征和实际解决的技术问题明确。
- [ ] 不复制他人专利文字；仅客观概述。
- [ ] 高风险对比文件必须进入 A/B/C 修改预案。

## 6. 客体合规

- [ ] 不属于科学发现、智力活动规则、疾病诊断治疗方法、动植物品种、原子核变换、平面印刷图案。
- [ ] 商业规则、调度策略、积分激励类方案必须绑定技术手段和技术效果。
- [ ] 软件/AI 方案写明输入数据的技术属性、处理流程、输出控制对象或技术效果。
- [ ] 涉及个人信息、地图轨迹、监管接口时标记数据合规待人工确认。

## 7. 摘要与附图

- [ ] 摘要不超过 300 字。
- [ ] 摘要只概括技术问题、技术方案要点、主要用途和技术效果。
- [ ] 摘要不含宣传词、商业价值表述或未在正文出现的新特征。
- [ ] 摘要附图最多一张，能代表核心技术方案。
- [ ] 附图为黑白线条图，编号和说明书一致。

## 8. 术语与标号

- [ ] 同一部件、步骤、模块、参数全文只用一个标准名称。
- [ ] 附图标号全局唯一；每个标号在说明书中至少出现一次。
- [ ] 权利要求、说明书、摘要、附图说明中的术语和标号一致。

## 9. 文风与禁词

- [ ] 不使用“领先、首创、先进、突破、填补空白、最佳、显著、大幅”等宣传词。
- [ ] 不使用“约、大概、左右、适当、较好、可能、容易、基本上”等不清楚表述，除非定义了边界。
- [ ] 不出现商标、竞品名、源码 URL、内部项目代号，除非作为已核验背景且必要。

## 10. 提交前门禁

- [ ] 26.3 / 26.4 审查关闭所有严重问题。
- [ ] 22.2 / 22.3 审查给出最危险对比文件和三步法结论。
- [ ] A/B/C 权利要求修改预案已准备。
- [ ] 待确认项清单已单独列出。
- [ ] 明确声明：AI 草稿必须由具备代理资质的人工复核后提交。
