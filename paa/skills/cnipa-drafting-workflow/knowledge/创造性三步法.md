# 创造性三步法

本参考用于按中国专利审查口径分析发明是否具有突出的实质性特点和显著的进步。三步法是判断工具，不应被简化为关键词相似度或专利数量统计。

## 第一步：确定最接近的现有技术

优先考虑与发明目的、用途、技术领域和技术效果最接近，且公开核心技术特征最多的单一对比文件。需要确认：

- 公开日在申请日或优先权日前；
- 文献身份、公开文本和相关段落可核验；
- 所选起点是本领域技术人员现实可选的技术起点；
- 不把多篇文献拼接成虚构的“最接近现有技术”。

## 第二步：确定区别特征和实际解决的技术问题

1. 按权利要求的完整限定逐项对照，列出被对比文件直接、无歧义公开与未公开的特征。
2. 分析每项区别特征在本申请中产生的技术效果；多个特征存在功能联系时，应整体分析其共同效果。
3. 根据该效果客观确定“实际解决的技术问题”。

实际技术问题应当：

- 与区别特征产生的技术效果相匹配；
- 采用中性表述，不包含区别特征本身；
- 不暗示或指向本申请的解决手段；
- 不是未经证明的宏大目标，如“全面提高智能化水平”。

若区别特征没有被说明书证明产生相应效果，不能仅在评审意见中事后赋予该效果。

## 第三步：判断是否存在技术启示

判断现有技术整体上是否给出将区别特征用于最接近现有技术、以解决上述实际技术问题的动机。重点核查：

- 其他对比文件中的相关手段是否解决相同或相近问题；
- 该手段在另一文献中的作用是否与本申请中的作用相同；
- 组合是否符合技术逻辑，是否需要改变原系统的基本原理；
- 组合后能否合理预期获得本申请效果；
- 所谓公知常识是否有教材、标准、工具书等证据，或属于无需举证也显然知晓的常规手段；
- 是否存在相反教导、长期未解决需求、预料不到的效果或协同作用。

不得在知晓本申请后倒推组合路径。仅因各个特征分别“已知”，不能当然得出特征组合显而易见。

## 算法、AI 和商业规则相关方案

- 对权利要求记载的全部特征作整体评价，不应简单割裂算法特征与技术特征。
- 如果算法或商业规则特征与技术特征在功能上相互支持、相互作用，其贡献应在技术问题、技术手段和技术效果链条中评价。
- 仅更换应用名称、数据标签、模型名称或业务场景，而处理机制与效果没有技术变化，通常难以形成强创造性。
- 更有价值的区别点往往来自：输入数据与技术对象的特殊关系、约束驱动的处理机制、模型输出对物理过程的闭环作用，以及由此产生的可验证技术效果。

## 证据绑定表

每项创造性结论至少记录：

| 项目 | 应记录内容 |
|---|---|
| 权利要求版本 | 被评价的具体文本和版本日期 |
| 最接近现有技术 | 公开号、公开日、相关段落或权利要求 |
| 区别特征 | 精确到权利要求技术特征 |
| 技术效果 | 说明书依据及必要的实验依据 |
| 实际技术问题 | 不包含答案的中性表述 |
| 组合证据 | 第二文献或公知常识证据及其作用 |
| 结论 | 有无技术启示、确定性和剩余风险 |

未经核实的文献只能标为“检索线索”，不得作为确定性 X/Y 对比文件或评分事实。

## 修改策略

- **A 方案：**保留核心区别机制，强化特征之间的作用关系；
- **B 方案：**加入能直接产生关键效果的约束、反馈或数据关系；
- **C 方案：**加入说明书原已公开的参数、异常处理或具体场景限定。

修改必须以原始申请文件为依据，不能为提高评分创造新的实施事实。语言润色不能替代真实技术区别。
