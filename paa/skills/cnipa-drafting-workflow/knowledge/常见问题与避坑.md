# 常见问题与避坑

本参考用于提交前快速识别中国发明专利申请中的高频结构性问题。修复顺序应优先处理技术事实和逻辑闭环，再处理权利要求层级，最后进行语言润色。

## 高频问题表

| 问题 | 主要风险 | 建议修复 |
|---|---|---|
| 模块或步骤堆叠，没有数据流和作用关系 | 技术方案不清楚，创造性贡献难以识别 | 补写输入、处理、中间状态、输出和反馈关系 |
| 只写“用于优化/识别/预测”的结果 | 缺少实现手段，可能不充分公开 | 写出关键计算、约束、控制或结构关系 |
| 仅增加“AI/大模型/数字孪生”标签 | 客体适格、充分公开和创造性均偏弱 | 说明模型结构或训练机制、场景数据内在关系及对技术过程的作用 |
| 技术问题中直接写入解决手段 | 创造性分析带有事后偏见 | 根据区别特征产生的效果，中性重述实际技术问题 |
| 各特征分别已知就认定组合显而易见 | 忽略组合动机和协同效果 | 核查技术启示、作用是否相同、组合障碍和预料不到效果 |
| 独立权利要求只覆盖愿望或业务规则 | 缺少必要技术特征 | 用删除测试补齐形成技术效果所需的核心限定 |
| 从属项只是同义改写 | 缺少答复和无效阶段的退守位置 | 布置核心机制、关键约束、异常分支、参数和场景梯度 |
| 术语、编号、引用关系前后不一致 | 不清楚、形式缺陷或保护范围争议 | 建立术语表并逐项校对在先基础与引用关系 |
| 参数或范围没有确定方法 | 无法实施或不受支持 | 补单位、测定条件、选择依据、边界和代表性实施例 |
| 忽略空数据、冲突、超时、越界、版本不一致 | 工程闭环不完整，效果不可信 | 补异常检测、降级、回退、终止或容错机制 |
| 用绝对效果或宣传语 | 缺乏依据，降低文本客观性 | 改为有条件、可测量且有证据支持的技术效果 |
| 背景技术无依据地承认“业内普遍采用” | 可能形成不利自认 | 仅陈述已核验事实，并准确限定缺陷条件 |
| 使用商品名或型号限定核心方案 | 范围不清或不必要收窄 | 改写为相应技术结构、协议或功能条件 |
| 一个申请并列多个无共同构思的发明 | 单一性风险、叙事发散 | 确定共同特定技术特征，必要时拆分申请 |
| 摘要复制权利要求或写成宣传文案 | 超字数、信息失焦 | 在 300 字内概括问题、核心手段和主要用途 |
| 通用“处理器+存储器”装置项没有执行关系 | 保护价值有限，可能只是方法换壳 | 明确处理器执行步骤、模块交互及技术对象 |
| 引用的对比文件未经核验 | 新颖性/创造性结论不可审计 | 核实公开号、公开日、文本位置和权利要求版本 |
| 为提高评分补造实施方式或数据 | 真实性、充分公开和修改超范围风险 | 标为待确认，补真实验证或收窄主张 |

## 提交前七道检查

1. **事实门：**所有结构、步骤、参数、数据和效果都来自技术人员确认或现有材料。
2. **客体门：**方案使用技术手段解决技术问题并获得技术效果；算法与技术特征整体成立。
3. **检索门：**最接近现有技术及关键组合文献已经核验，检索结论可追溯。
4. **创造性门：**区别特征—技术效果—实际技术问题—技术启示形成完整证据链。
5. **公开门：**本领域技术人员无需创造性劳动即可实施，关键实验和异常流程已有交代。
6. **支持门：**权利要求每项特征在原始说明书中有直接、无歧义依据，并保留合理梯度。
7. **一致性门：**名称、术语、编号、附图、权利要求、说明书和摘要相互一致；摘要不超过 300 字。

任何一项不通过，应记录为阻断项或剩余风险，不得用综合评分把它平均掉。

## 2026 年 AI 申请特别提醒

- 将全部权利要求特征作为整体评价，并不意味着算法标签可以替代技术限定。
- 模型训练类方案通常需要公开对贡献必要的模型关系、训练步骤和参数。
- 具体领域应用通常需要公开算法如何结合场景，以及输入输出之间的内在关系。
- 若这些关键手段不是公知常识且未公开，可能构成说明书公开不充分。
