# 证据约束评审协议

本协议蒸馏自网页incoPat Agent IPR、incoPat开放API、PAA、PatentARA、CNIPA门禁、双模型固定证据复评和AHP/SEM多轮结果。它解决的主要问题是：不同系统的“分数”测量对象不同，若直接平均，会把证据缺口、结构完整度和法律风险混成一个不可解释数字。

## 1. 五层证据账本

每项结论必须标明证据层，不得跨层偷换：

| 层 | 可证明 | 不能证明 |
|---|---|---|
| 网页智能体/IPR | 该次项目是否完成、候选池及平台报告结论 | 全库无对比文件、组合无启示 |
| incoPat检索结果 | 召回到的专利、字段、相似度、数量 | 相似度高即破坏新颖性，零命中即有创造性 |
| claim/spec原文 | 某文献明确公开的必要技术特征 | 申请日资格、D1+D2必然可组合 |
| 申请文件/PAA | 权项结构、文字支持、跨层绑定、形式问题 | 申请日前真实实现、实际效果 |
| 工程与法律事实 | 代码/日志/实验、申请日、优先权、代理师判断 | 自动评分器可替代审查结论 |

证据状态统一为：

- `confirmed`：已由原文、申请日前材料或确定性规则直接确认；
- `supported`：有可靠间接证据和可复核推理链；
- `inferred`：合理推断，尚非直接证据；
- `needs-confirmation`：必须由技术人员、申请日资料或代理师确认；
- `unverified`：仅摘要、搜索片段、模型记忆或未核验摘录；
- `contradicted`：被更高质量证据否定。

## 2. 检索审计纪律

### 最小检索包

对每个实质修改后的独立权利要求：

1. 一次独权语义检索；
2. 一至两组围绕区别关系的布尔检索；
3. 两至四件高相关文献的`info`与`claim`原文；
4. 对决定创造性的说明书段落调用`spec`；
5. 记录检索式、时间、接口、返回量、错误、降级字段和文献资格。

语义检索负责跨术语召回，布尔式负责可复现性，`claim/spec`负责法律特征映射。任一路失败不应抹去其他路的有效证据。

### 失败语义

- 网页项目未生成报告：`NO_CONCLUSION`；
- 拟对比文件仓为空：`EVIDENCE_MISSING`；
- 429、超时或“程序繁忙”：`PROVIDER_DEGRADED`；
- 字段无权限：`FIELD_UNAVAILABLE`，不得写“该字段不存在”；
- 搜索式零命中：只说明该表达式零命中，不给N/I自动加分；
- 报告称“未检索到影响文件”：仅限该次输入、候选池和平台模型。

### 日期资格

新近高相关文献可能是强近邻但不是现有技术。未确认申请日/优先权日时：

- 可用于观察技术赛道收敛和修改后重合风险；
- 不得直接作为22.2/22.3否定依据；
- 输出必须带`date-eligibility`待办。

## 3. 三层决策，不做一锅平均

### A. 硬门禁

- 客体适格；
- 单篇文献是否覆盖独权全部必要技术特征；
- 26.3充分公开与26.4清楚/支持；
- 证据真实性和公开号溯源；
- 确定性权项引用、摘要、编号和格式缺陷。

任何FAIL都阻断放行。PAA Seal通过只表示结构和绑定可审计，不表示工程事实、日期资格和组合启示已关闭。

### B. 结构成熟度

由PatentARA、形式检查、支持图谱和PAA结构提供。它适合发现：

- 单篇全要素覆盖；
- 权项要素分解；
- 说明书词面支持映射；
- 术语、摘要和形式缺陷；
- 多版本间的结构变化。

长独权中只要每篇文献都缺少一个要素，结构分可能很高；因此它不是授权概率。

### C. 风险调整可专利性

AHP/SEM风险分还应计入：

- D1+D2组合动机和公知常识；
- 区别手段是否常规；
- 有益效果是否由区别特征导致且可验证；
- 新增机制是否为申请日前真实事实；
- 算法/教育/业务主题的客体风险；
- 检索覆盖和证据原文质量。

结构分高而风险分中等是正常结果，必须解释，不得强行拉齐。

## 4. 16项指标的证据锚点

| 指标 | 高分必须看到的证据 | 常见误加分 |
|---|---|---|
| S1 | 技术问题、技术手段、计算机内部技术效果形成因果链 | 只把业务名词改成“模块” |
| S2 | 独权必要特征由技术对象、状态、数据流或控制主导 | 罗列服务器、处理器 |
| S3 | 算法参数改变具体设备/数据处理状态 | 仅限定行业名称 |
| N1 | 最接近文件claim原文映射，不以相似度直接定性 | 语义分低即新颖 |
| N2 | 单篇全要素表及缺失要素 | top2未覆盖即全库无X文件 |
| N3 | 必要关系组合未被单篇直接无疑义公开 | 长权项造成形式性未命中 |
| I1 | 区别手段非常规或改变既有机制工作方式 | 堆叠CAS、哈希、状态机 |
| I2 | 前一机制改变后一机制的输入、状态或允许动作 | “一起使用效果更好” |
| I3 | D1+D2没有组合动机，或组合会破坏其原理/需反向改造 | 只说单篇不公开 |
| I4 | 区别特征对应真实对照、边界或故障实验 | 理论效果、模型自评 |
| D1 | 字段、状态、公式、阈值、事务边界和退化规则 | 黑盒算法名 |
| D2 | 正常、重复、乱序、迟到、失败、空集合等路径 | 只有一个顺利实例 |
| D3 | 申请日前日志/实验，指标口径和对照组明确 | “显著提升”无数据 |
| Q1 | 独权最小闭环均有支持，未把待确认特征上提 | 为提分无限加限定 |
| Q2 | A/B/C退守梯均为完整技术方案 | 从权仅换数值 |
| Q3 | 对象、版本、状态、标识和图号前后一致 | 语言流畅但对象漂移 |

## 5. 创造性第三步的最小攻击表

每案至少回答：

1. D1是谁，为什么是最接近而非仅相似度最高；
2. D1缺少哪些独权必要关系；
3. 这些关系共同解决的实际技术问题是什么；
4. D2或公知常识提供了什么动机；
5. 将D2加入D1是否需要改变D1原理、数据对象或执行时序；
6. 区别特征是否形成不可绕过的状态/权限/版本门控；
7. 效果是否由该区别关系导致；
8. 若把区别特征拆开，各自是否只是常规手段。

真正可守的创造点通常是“新的约束关系”，而不是新名词。例如：

- 状态不可回退而非“有状态”；
- 回收完成成为后续汇聚放行必要令牌，而非“有权限控制”；
- CAS成功后才传播下游失效且失败不污染现行链，而非“有版本管理”；
- 同一锁定证据版本同时约束输入访问和逐输出引用，而非“有RAG校验”。

## 6. 支持与充分公开的校准

词面支持率低时先判断：

- 是否只是权项上位化、同义改写或分散在多个段落；
- 说明书是否实际给出字段、状态、算法和路径；
- 是否仅有文字描述但缺申请日前工程事实；
- 是否把提交后提出的新机制倒推成原始事实。

因此输出区分：

- `textual_support`：文字稿是否能找到对应公开；
- `engineering_fact`：申请日前是否真实存在；
- `reproducibility`：本领域技术人员能否实现；
- `scope_support`：上位概括范围是否由实施例支撑。

## 7. 整改意见的质量门槛

合格建议应包含：

- 对象：权利要求号/特征/说明书段落/检索式；
- 根因：哪一门禁、哪一组合攻击或哪一证据缺口；
- 动作：删除、下沉、补字段、补异常路径、补原文、补实验或重检；
- 完成标准：可观察的PASS条件；
- 真实性状态：`confirmed/inferred/needs-confirmation`；
- 对A/B/C权项及商业价值的影响。

“加强创新性、优化语言、补充实施例”不满足要求。
