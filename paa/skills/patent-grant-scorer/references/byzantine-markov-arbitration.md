# 拜占庭仲裁、跨轮状态与动态公平

## 1. 为什么不能只求一致

审查员、代理人、无效请求人和工程分析师的目标函数本来不同。分歧可能来自：

- 合法立场差异；
- 检索证据不同或版本过期；
- 申请日资格理解不同；
- LLM量表漂移、光环效应或提示词污染；
- 网页/API失败后把“未知”误当“无风险”；
- 低质量、复制或异常评分。

因此“一致”不等于正确，“离群”也不等于恶意。仲裁首先看证据，再看距离。

## 2. 当前稳健聚合规则

评分器对每个指标独立执行：

1. 计算专家分中位数、极差和MAD；
2. 依据`confidence × evidence_quality × status_factor × calibration × domain_fit`计算可靠性；
3. 四专家满足`n ≥ 3f+1`时，最大拜占庭容错`f=1`；
4. 只有“偏离显著、证据可靠性低、且不是旧版纯数字”的评分才进入疑似异常队列；
5. 最多降低`f`个疑似异常评分的权重，不删除原始记录；
6. 以`0.60×中位数 + 0.40×证据加权均值`形成指标中心；
7. 高证据少数意见不被压低，而是写入`high_quality_dissent`并触发人工复核；
8. 极差≥2.5、MAD≥1.0或疑似异常超过容错上限时，`review_required=true`。

这些阈值适用于1—9量表，是评审队列触发器，不是法律阈值。

## 3. 定向仲裁步骤

出现`review_required`时，不重新询问“你给几分”，而是：

1. 固定独权哈希和证据哈希；
2. 列出分歧最小命题，例如“D2是否教导把权限回收完成作为汇聚必要令牌”；
3. 为每方列出连续原文、申请日资格和特征映射；
4. 检查是否混淆单篇新颖性与多篇创造性；
5. 补一次只针对该命题的检索或技术事实确认；
6. 允许专家修改分数，但保留前值、原因和证据差异；
7. 仍无结论时保留风险分歧和较宽不确定区间，交代理师裁决。

禁止用多数表决消灭高质量反对意见，也禁止让单个专家在无原文证据下否决全案。

## 4. 马尔可夫评审状态

每轮状态记为：

```text
R_t = (
  claim_hash,
  evidence_hash,
  application_date,
  hard_gates,
  S/N/I/D/Q,
  disputed_indicators,
  closest_prior_art,
  engineering_evidence_status,
  decision
)
```

下一轮只需携带上轮状态和本轮增量，而不是把全部历史文本塞回上下文。原始证据仍保存在PAA证据层，可按引用展开。

### 状态转换分类

| 转换 | 含义 | 能否把分差解释为改稿效果 |
|---|---|---|
| 同证据、独权变化 | 固定证据A/B测试 | 可以，仍需看门禁 |
| 独权不变、证据变化 | 检索或原文补强 | 不可以，属于证据漂移 |
| 独权和证据同时变化 | 混合变化 | 不可以直接归因 |
| 哈希相同重新评分 | 量表/模型稳定性检查 | 可以观察评审漂移 |
| 哈希缺失 | 不可审计 | 禁止宣称分数提升 |

PatentARA重新检索后的分数与固定证据双模型分数不是控制变量实验；必须分别记录。

## 5. 可持续学习但不固化唯一最高标准

允许跨案沉积的知识：

- 哪类检索式召回了后来被审查员采用的文献；
- 哪类证据状态最能预测OA风险；
- 哪类整改动作真实关闭了门禁；
- 角色在特定技术领域的历史校准误差；
- 某时期、某IPC/技术赛道的相对分布。

不应跨案直接迁移：

- 具体公开号、区别特征或申请人事实；
- 未经OA/授权结果验证的“高分写法”；
- 为单案调出的阈值；
- 申请日后新增机制。

更新专家`calibration`或SEM参数时至少满足：

1. 使用真实OA、授权、驳回或无效结果；
2. 区分同族、分案和高度相关案件，防止数据泄漏；
3. 保留时间窗和技术领域；
4. 记录更新前后参数与回测；
5. 小样本只输出建议，不自动改权重；
6. 发现法律口径、检索库或案件构成漂移时重新校准。

## 6. 动态和相对公平

没有绝对不变的70分线。公平性依赖：

- 同一轮使用相同量表、角色、证据门槛和版本绑定；
- 同一技术赛道、申请阶段和时间窗内比较；
- 同时报告绝对风险点估计、证据置信度和同批百分位；
- 检索覆盖不同的案件不能只按总分排名；
- 硬门禁FAIL案件即使百分位高也不得放行；
- 分数变化应拆成“文本变化、证据变化、量表变化”。

评分器输出的`relative_position`只服务案件排序，不是授权标准。

## 7. 上下文压缩模板

跨轮只传递：

```yaml
round: 3
claim_hash: ...
evidence_hash: ...
hard_gates:
  subject_matter: PASS
  disclosure_support: CONDITIONAL
latent: {S: 7.1, N: 5.2, I: 4.7, D: 6.4, Q: 7.5}
disputes: [I3, I4]
closest_attack: D1 + D2 + motivation
confirmed_changes: [...]
needs_confirmation: [...]
next_queries: [...]
```

对某项有争议时再加载对应claim/spec原文，不把无关历史塞入当前轮。
