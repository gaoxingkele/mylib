# 来源路由

使用实际可用的最高置信度通道，并在 `query_log.csv` 记录实际通道、查询和失败原因。

## mylib 默认优先顺序

1. 提案材料和用户提供的文件；这些内容只标为“提案陈述”。
2. [`patsnap-search`](../../patsnap-search/SKILL.md) / [`incopat-search`](../../incopat-search/SKILL.md)：专利检索、相似专利、权利要求与说明书原文。
3. 智慧芽论文接口与 [`npl-prior-art-search`](../../npl-prior-art-search/SKILL.md)：论文发现、DOI/原文核验和引用追溯。
4. [`google-patents-search`](../../google-patents-search/SKILL.md)：结构化通道不可用或需要独立复检索时的专利通道。
5. 领域专项学术、标准、申报数据库，以及可用的 `Exa`、`Tavily`、`Brave`、通用 web 和已知 URL 阅读器。

## 按信息需求路由

| 需求 | 首选通道 | 降级方案 |
| --- | --- | --- |
| 提案主张提取 | 提案材料 | 要求补充材料或标注为开放缺口 |
| 专利新颖性与重叠 | 智慧芽 / incoPat 检索后逐件取原文 | Google Patents 检索、取件并运行 `gp_verify.py` |
| 论文前沿与可行性 | 智慧芽论文接口 + NPL 路由 | 领域学术数据库或通用 web，明确覆盖损失 |
| 申办方或对比方披露 | 官方申报文件或财务数据库 | 官方域名 web |
| 政策、标准及公开部署状态 | 官方来源或可用实时检索 | 通用 web + 已知 URL 阅读器 |

## 原文与降级规则

- 检索列表、摘要和 AI 相似比对只产生候选，不直接支撑正式 X/Y/A 判断；引用前保存专利原文证据或论文 DOI/原文定位。
- 重要结论尽量跨两个独立数据库复核；数据库命中差异如实记录，“未检出”不得改写为“不存在”。
- 若提案材料薄弱或结构化检索不可用，在 `method_decisions.md` 记录降级，说明无法完整核查的内容，并降低新颖性、重叠和完整性主张的置信度。
- 不得暗示仅凭公开检索即可证明内部重复项目排查的完整性。
