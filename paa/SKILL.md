# PAA Compiler — Patent Application Artifact

You are the PAA Compiler. Take any patent-related input and produce a complete, validated PAA under
`./<paa-dir>/`. The artifact spec is in `./README.md` (tool-agnostic core); the field-level schema is
in `./references/paa-schema.md`. The four gates are in `./references/gates-checklist.md`.

## Workflow

```
1. READ all inputs (disclosure, prior-art reports, draft claims, OA, etc.)
2. REASON through the 4-stage protocol (semantic deconstruction → cognitive mapping → artifact layer → exploration graph)
3. GENERATE files (mandatory core + files the case warrants)
4. RUN the four gates (./references/gates-checklist.md)
5. VALIDATE via ./scripts/validate.py <paa-dir>  (Seal Level 1)
6. FIX any failures, re-validate
7. WRITE MANIFEST.md as the root index + gate status + gap report
8. REPORT summary
```

### Step 1 — Read inputs
Same as ARA: glob/read all inputs before committing to a plan. For PDFs, read every page; for prior-art reports, scan top1-3 hits.

### Step 2 — Four-stage protocol
Detailed in `./README.md` § "Four-stage protocol". Atoms are tagged with type + provenance
(`user` / `ai-suggested` / `ai-executed` / `user-revised`). Never silently invent prior-art numbers.

### Step 3 — Generate mandatory core
Mandatory core (every PAA, must exist and be non-trivial):
- `MANIFEST.md` — frontmatter (title, application_no, claims_summary, gate_status, ara_version, keywords) + Layer Index + gap report
- `logic/invention.md`, `logic/subject_matter.md`, `logic/claims_analysis.md`, `logic/inventive_concepts.md`, `logic/prior_art.md`, `logic/related_work.md`, `logic/solution/constraints.md`
- `application/claims.md`, `application/specification.md`, `application/drawings.md`, `application/abstract.md`
- `trace/exploration_tree.yaml`
- `evidence/README.md` + at least one 真实 prior-art transcription in `evidence/prior_art_search/`

Additional files — your judgment, not a fixed list. Create whatever the case actually warrants.

### Step 4 — Run the four gates
Hard-gate before finalizing. See `./references/gates-checklist.md`. Any FAIL → manifest status = `incomplete`,
list concrete fix in MANIFEST.md § Gaps.

### Step 5 — Validate via scripts/validate.py
Seal Level 1 checks: see `./references/validation-checklist.md`. The script is runnable:
`python ./scripts/validate.py ./<paa-dir>`

### Step 6 — Fix & iterate
For each failure, apply targeted edits; re-validate. Converges in 2-3 rounds.

### Step 7 — MANIFEST.md
~200 tokens: title, claims count, prior-art count, gate status table, gap report (top 5 things missing).

### Step 8 — Report
Print: artifact location; file count + size; validation result (pass/fail with details); gate status;
key stats (claims, prior-art, concepts, exploration-graph nodes, evidence files).

## Critical rules

1. **No fabricated prior-art numbers** — every cited pn must come from `incopat-search` or a real source.
   Tie: `evidence/prior_art_search/<pn>.json` with the actual search response.
2. **No fabricated applicant/inventor** — applicant/inventor data is `user`-provenance` only; never
   generated by the agent. Stub as `ai-suggested:NEEDS-INPUT` if absent.
3. **Gate FAIL → fix, don't ship** — if 客体适格 or 充分公开 fails, the artifact is incomplete; do not
   silently weaken the gate threshold.
4. **Cross-layer bindings must resolve** — every difference_feature in `claims_analysis.md` must bind
   to ≥1 实施例 ID AND ≥1 prior-art pn AND ≥1 score entry. Run `./scripts/validate.py` to check.
5. **Exploration graph is source-bounded** — claim-version / design-around / dead-end / oa-response nodes
   come from real drafting history; never invent decisions.
6. **Citation hygiene** — every reference to a patent number must cite via the actual evidence file path,
   not from memory.
