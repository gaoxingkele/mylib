> 示例版本采用精简表述以演示 PAA 结构；真实提交版本含完整五要素 + ≥2 实施例 + 数值实例。详见项目源文件。

## 技术领域

本发明涉及企业 AI 中台 / 检索增强生成（RAG）防幻觉技术领域。

## 背景技术

现有 RAG 系统的检索阶段通常采用多路并行检索并通过倒数排序融合算法对候选结果进行融合，对融合后的结果由大语言模型生成答复。然而该路径存在两类显著缺陷：

**CN121636664A（2025-12 申请）** 披露了"基于多维异构知识召回增强的混合检索方法及系统"，其多路并行检索+RRF 融合使用**固定**来源权重，未根据查询类型差异动态调整；其知识图谱角色为扩召回，权利要求止步于检索端，无生成端约束。

**CN121659916A（2026-01 公开）** 披露了"基于知识图谱与大模型混合驱动的对话生成方法"，其将结构化事实数据**注入**预设的约束性提示模板（含角色设定、禁止外部信息、格式规范、拒答策略）以约束大语言模型生成——但该方案中生成约束与检索过程解耦，权利要求完全止步于"约束模板内容"，"与未"利用检索校验结果端。

上述两类现有方案均无法同时满足：①多路融合时按查询类型差异化路由；②检索端对候选结果的图谱一致性校验；④生成端结构性消费检索校验结果。

## 发明内容

### 技术问题

针对上述现有方案的不足，本发明要解决的技术问题是：①单一检索引擎能力边界；③检索结果与图谱矛盾；⑤生成内容缺乏结构性约束导致的忠实性问题。

### 技术方案

采用基于知识图谱校验-约束闭环的方法，包含三层增强：

1. **查询层**：将查询请求中的关键短语与知识图谱实体匹配，将一跳邻居实体名称作为扩展关键词注入关键词检索查询语句；
2. **检索层**：在 RR 融合执行前对候选结果进行图谱关联路径匹配，对不存在关联路径的候选施加惩罚因子降权；
3. **生成层**：对重排序后每个候选构建结构化封箱，按校验结果裁决为可用态/隔离态，仅可用态封箱装配进大语言模型输入；元适配层生成结构化元策略对象驱动生成端门控——**约束通过"仅可用态封箱被装配进输入"这一结构性事实实现**，提示词不承载任何注入的约束事实或约束指令。

### 有益效果

- 首条命中率显著提升（实测口径，未给出绝对数字）
- 检索层路径惩罚显著降低与图谱矛盾候选的权重
- 生成内容与图谱已知事实一致性显著提升，隔离态封箱因未进入模型输入而结构性不可被引用
- 检索→生成闭环由图谱统一驱动

## 具体实施方式

### 实施例一

以"查询电力变压器故障诊断 RAG 场景"为例，说明本发明 Seal-and-Adapt 生成约束的完整步骤。各步骤对应区别特征 D01-D09（详见 logic/claims_analysis.md）。

**区别特征绑定表**

| 步骤 | 区别特征 | 机制 |
|---|---|---|
| 1 | D01 查询层图谱增强 | 实体邻居扩展注入检索查询语句 |
| 2 | D02 动态权重 RRF | 按查询类型分类调整通道权重 |
| 3 | D03 路径惩罚减法校验 | 对图谱无关联候选施加惩罚因子 |
| 4 | D04 MMR 去冗余 | 最大边际多样性重排序 |
| 5 | D05 封箱构建 | 候选结构化封箱 |
| 6 | D06 封箱裁决 | 可用态/隔离态分流 |
| 7 | D07 元策略对象生成 | 结构化控制配置（非文本） |
| 8 | D08-D09 证据装配 + 元门控生成 | 仅可用态装配 + 元门控拦截 |

**步骤详情**：

1. （实施例一步骤1，对应 D01）查询请求 = "查询请求"；将"色谱"作为明确实体匹配知识图谱，跳邻居实体列表 = {"油光谱", "故障类型", "诊断方法"}，作为扩展关键词注入关键词检索的查询语句；
2. （实施例一步骤2，对应 D02）查询类型分类识别到明确实体"色谱"，分类为**实体查询**；动态权重 w_K=0.3, w_V=0.3, w_G=0.4；按公式 RRF_score(d)=Σ(w_r/(k+rank_r(d)))，k=60 计算每条候选的融合分数；
3. （实施例一步骤3，对应 D03）实施例一步骤：对每条候选的核心实体检查其与"色谱"实体的图谱关联路径——发现候选 ENV-Q08 的"电力设备维修方案"实体与"色谱"无关联路径，施加惩罚因子 0.7，置信度得分乘以 0.7 后从 0.85 降至 0.595；
4. （实施例一步骤4，对应 D04）λ=0.7，对融合后的 top 12 候选做去冗余；
5. （实施例一步骤5，对应 D05）对 top 5 候选构建结构化封箱，字段包括候选内容 / 来源通道 / 图谱路径证据 / 惩罚标记 / 一致性状态；
6. （实施例一步骤6，对应 D06）ENV-001（色谱诊断）→ 可用态；ENV-Q08（电力设备维修方案，被惩罚）→ 隔离态；隔离态封箱不进入后续生成阶段的输入；
7. （实施例一步骤7，对应 D07）{available_set: [ENV-001], quarantine_set: [ENV-Q08], output_schema: {required_fields: ["诊断方法", "诊断依据"]}}；
8. （实施例一步骤8，对应 D08-D09）仅 ENV-001 装配进大语言模型结构化证据输入；提示词不承载任何注入的约束；元策略对象驱动生成端门控——若模型尝试引用 ENV-Q08 内容则被拦截。
