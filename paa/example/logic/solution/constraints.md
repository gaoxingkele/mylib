# 撰写策略（方案 / 限制 / 决策）

## 限制与假设

- 大语言模型选用为外部 API 调用，不属于本案权利要求限定的"自有模型"——生成端约束在 API 调用者一侧执行
- 知识图谱存储于图数据库（如 Neo4j），Cypher 查询；其他存储形式需替换查询接口
- 三级安全网默认参数（TH1/TH2/Top1 保底）在不同领域需重新标定

## 撰写策略

- **独权叙事重心**：从最初的"三引擎并行检索融合"翻转到 v3 的"图谱校验-约束闭环的 RAG 防幻觉方法"——图谱从"第三检索源"变成"查询理解器 → 检索校验器 → 生成约束器"三位一体
- **前序承认范围**：仅承认"多路并行检索 + RRF 融合"为已知技术（最接近现有技术 D01 的核心），其余技术贡献均在特征部分
- **从权梯度退守**：从"事实注入"（v1）→ "冲突标记注入"（v2）→ "封箱裁决 + 元门控，零注入"（v3），每一步对应一份对比文件的机制级绕行
- **多主题覆盖**：方法 + 装置 + 介质 + 电子设备，独立权利要求 14 条总数

## 机制级绕行决策（重要）

**判定口径**：对方权利要求里的**动词**就是它圈走的机制；绕行要换掉动词，而不是换动词的宾语。

- **v1 → v2**：换内容（事实三元组 → 冲突标记）— **不构成机制级绕行**，因"注入系统提示"动词本身仍是对方独占
- **v2 → v3**：换机制（注入 → 封箱裁决 + 元门控）— **构成机制级绕行**，因"注入"动词整个消失
