## D02: CN121659916A（基于知识图谱与大模型混合驱动的对话生成方法）— 冲突文件 2

### 元数据

- **pn**: CN121659916A
- **applicant**: (背景技术中未引用具体申请人信息；以"对话生成在先申请"表述)
- **pd**: 2026-01（语义检索结果日期附近，pn 真实，ad 字段从 incoPat search 返回的 pd 字段获取）
- **relationship**: **conflicts**（覆盖本案生成层原方案）
- **证据文件**: evidence/prior_art_search/CN121659916A.json + evidence/prior_art_claims/CN121659916A.md
- **relevance**: X-文件（独立危险）

### 它覆盖了什么（机制级）

- 导航式检索 → 获取结构化事实
- **将结构化事实数据注入预设的约束性提示模板**（生成文本约束提示，含角色设定/禁止外部信息/格式规范/拒答策略）
- LLM 基于提示生成初始应答
- 生成后字段级事实校验 + 逻辑一致性检查
- 校验失败 → 降级响应策略（拒答/澄清/转人工）

### 它没覆盖什么（本案的差异空间）

- **多路并行检索 + RRF 融合**（对方是单源 KG 导航检索）
- **检索层路径惩罚校验**（对方无检索端校验环节）
- **结构隔离式生成约束**（对方是"提示词注入"，本案是"封箱可用性裁决 + 元门控"——隔离态根本不入模型输入）

### 关键机制差异：注入 vs 结构隔离

| 维度 | CN121659916A | 本案 |
|---|---|---|
| 约束载体 | 文本（事实 / 规则 / 模板） | 无（封箱可用性 + 元策略） |
| 坏内容处理 | 提示词指令"不得引用 X" | 坏内容封"隔离态"、从模型输入移除 |
| 检索/生成耦合 | 解耦（生成端独立决策） | 强耦合（生成端消费检索校验结果） |

### 三步法预答辩逻辑

- 区别特征 = D05 + D06 + D07 + D08 + D09（封箱+元门控，零注入）
- 实际解决的技术问题 = "检索校验结果无法被生成端结构性消费"
- 非显而易见性论证 = 替换"注入"这个**动词**而非换内容（机制级绕行，详见 design-around/round_3_injection_to_sealing.md）

→ 详见 logic/inventive_concepts.md §C03
