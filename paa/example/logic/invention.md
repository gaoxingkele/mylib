# 发明要素

## 技术领域

企业 AI 中台 / RAG（检索增强生成）检索与防幻觉技术领域。

## 技术问题（Technical Problems）

- **T1**: 单一检索引擎（关键词 / 向量 / 图谱）能力边界明显；多路结果融合权重多为静态固定，未按查询类型动态调整。
- **T2**: 检索结果冗余；低召回场景健壮性不足；知识图谱未充分用于查询理解、检索校验、生成约束三层协同。
- **T3**: 即使检索充分，大语言模型生成阶段仍可能产生"幻觉"——生成内容缺乏与领域事实的一致性约束。
- **T4**: 现有生成约束方案（如 CN121659916A 把结构化事实"注入"提示模板）与检索过程解耦，未利用检索端的校验信号。

## 技术手段（Technical Solution）

- **S1**: 三引擎并行检索（BM25 / Embedding ANN / Neo4j 多跳）。
- **S2**: 基于查询类型分类的动态权重 RRF 融合（实体查询 / 语义查询 / 精确查询对应不同权重集）。
- **S3**: 检索层图谱关联路径"减法"校验：对与查询实体在图谱中无关联路径的候选施加惩罚因子降权。
- **S4**: MMR 多样性重排序；三级安全网降级保底。
- **S5**: 知识图谱三层增强（查询层实体邻居扩展 / 检索层路径惩罚 / 生成层封箱裁决 + 元适配门控）。
- **S6**: **Seal-and-Adapt 生成约束**（本案核心）：封箱构建 → 裁决分流（可用态 / 隔离态）→ 元策略对象生成 → 仅可用态封箱装配 → 元门控生成（取代任何"注入"动作）。

## 技术效果（Technical Effects）

- **E1**: 知识检索首条命中率 ≥ 85%（实测口径）；检索响应延迟 ≤ 100ms。
- **E2**: 检索层路径惩罚显著降低与图谱矛盾候选的权重。
- **E3**: 生成内容与图谱已知事实一致性显著提升；隔离态封箱因未进入模型输入而结构性不可被引用，区别于对比文件 2 的"注入式"约束。
- **E4**: 检索 → 生成 闭环由图谱统一驱动，区别于对比文件 1（止步检索端）与对比文件 2（生成约束与检索解耦）。
