# 多机 Coding Agent 驾驶舱：项目目标与执行总计划

2026-11-22 · 设计与规划交付。本页作为两个仓库共同的执行入口，维护总目标、优先级、里程碑及放行条件。三轮评审决议保留在下文。接口、数据表及轮换细节见[模块设计](README.md)。

## 总目标与完成标准

在 Windows 和 Android 打开驾驶舱，用户能按项目找到同一任务，看清各机器和 Coding 工具分别做了什么、结论依据何在、哪项验证尚有分歧、哪个账号有额度继续。用户能让另一窗口接手或复验，逐次确认发往窗口的反馈，并将验证有效的方法发布到 mylib，查到各窗口实际采用的版本。

| 产品目标 | 完成时应能出示的证据 |
| --- | --- |
| 跨机任务连续 | 同机换工具、跨机接手、两工具并行复验各有一次完整记录；未同步的补丁、迟到的旧执行和不同代码基线均可辨认。 |
| 本地与全局共享同一份决策记录 | 本地 wiki 与中央数据库可按记录 ID、版本和正文摘要核对；断网后能补传，源机离线时仍能查看授权正文。总管回答可回查原轮次或原工件。 |
| 全局容量可判断 | 每个已确认步骤可追到该计费账号的后续查询。覆盖已接入工具的周余量、下次重置、数据单位、最后成功时间；共享池、过期、限流和不支持均有明确表示。 |
| 双端反馈可控 | 选择任务下的具体执行，预览并确认一次；核对目标、内容和回执。取消、目标失效及仅查看时，发往终端的输入均为零。 |
| mylib 持续改进可追溯 | 一个真实失败案例能从父版本、候选、独立复验、人工采纳追溯至发布版本、窗口加载回执及回退。证据不足的候选可以留在影子评测。 |

**执行状态。** 已有冻结标签及旧 mylib 技能 MCP 的部署记录。新增业务 MCP、Hook、额度采集、双端驾驶舱、RSI 评测与加载回执已进入 0.2.81 隔离试点；真实账号、真实设备和生产放行分别验收。运行证据、产物和未决条件以[试点交付记录](pilot-status.md)为准。 [模块设计与演练](README.md) · [既有中央服务](/D:/aicoding/supermonoagent/docs/central-mylib-mcp.md)

**数据路径。** 开发步骤 → 本地 wiki 与持久队列 → 中央 MCP 同事务写入事件、wiki 正文、回执及额度待办 → 授权采集器回写查询结果 → 总管按任务凝练并按需取证 → 双端驾驶舱。原终端字节流保留用于现场查看与补证；需要跨房间汇聚所有授权 Agent 字节时，另启隔离试点，验证来源授权、断点恢复与背压后放行。

**数据库试点。** 中转服务器本地磁盘使用 SQLite，服务统一写入；采用含已知 WAL 修复的运行版本，或先选回滚日志模式。先按 30 天或热库约 256 MiB 评估轮换。用 Backup API 生成一致备份、校验并演练恢复后，再切换新库。保留活跃执行、最新额度、未结任务、去重回执、有效 wiki 正文及历史定位。归档另设容量与留存预算。轮换前确认可接受的数据损失窗口、恢复时长及独立备份位置。 [换库步骤与保留规则](README.md#备份和换新库)

## 一次任务怎样贯穿系统

1. **建任务与接手。** 在授权项目下建立稳定的 `task_id`。在本机用 Codex 做修复，在另一台机用 Claude 接手，或用 Grok 验证，都各有 `attempt_id`。每次执行绑定主机安装 ID、宿主会话和代次、计费账号及工件版本。两人同时接手时，服务器原子检查前任 ID；旧执行的迟到记录只进入其历史。验证者并列，基线相同时才合并比较，意见冲突进入待裁决。
2. **落地与汇总。** 复用已有 wiki 写入器，保留结论、理由、取舍、验证证据与待办。本地队列向中转服务器补传同一份获准共享的正文；MCP 按项目授权一次提交事件、wiki 版次、幂等回执及额度查询待办。接手包引用工作树或补丁摘要，跨机取不到未提交改动时标「待同步」。总管先查全局任务摘要，再展开对应执行或冲突证据，巡检总输入以 8,000 token 起测。终端字节流继续用于查看原窗口和补证。
3. **额度。** 每次开发步骤提交成功都关联一次后续查询，查询和心跳写回有独立来源，避免触发循环。驾驶舱按账号与共享池显示周剩余、短周期限制、下次重置、采集时间及状态。同池的多个窗口引用同一结果，查不到显示待核对或过期。配额不足可提出接手建议，决定接手时核对任务所需模型、可访问工件和接手方的实际额度。
4. **反馈。** 总管聊天、定位窗口、准备草稿和发送是不同操作。发送确认页展示任务、机器、原窗口标题、工具、执行角色和完整正文。确认绑定 `request_id`、执行与宿主代次、正文摘要和有效期。宿主收到后重新校验权限、内容和代次。已具备持久去重及回执查询能力的宿主可提供「确认发送到…」；普通 PTY 先提供「准备草稿」，用户在目标窗口的原有发送入口确认。纯查看产生的 PTY 输入和 resize 帧均为零。 [目前的会话能力](/D:/aicoding/supermonoagent/.omx/worktrees/conversation-journal/docs/conversation-journal.md)

## mylib 与 RSI 如何持续升级

- **从失败产生候选。** mylib 页首先显示当前任务所用 skill、harness 和实际版本。「进化记录」展开父版本、改动点、验证工件、适用工具及负例。首个候选可针对「无输出被误报阻塞」：孤立的安静窗口显示「观察中」，有待确认、限额或错误证据才发对应提醒。须先建立父代基线并观察到该误报。
- **谁给效果计分。** 模型提出病因和改动，人工盲标或独立测试作为结果依据。对告警规则，用同一时间线分别回放父代和候选，同时抽样未告警窗口以检查漏报。对可能改变后续行为的 skill 或 harness，须在相同代码与输入上独立执行两套流程。按任务或项目聚类，单独标明工具版本、人工干预、额度池和时间预算。点击、下载与共享池额度变化只用于解释使用情境。 [metaRSI](../../skills/meta-rsi/SKILL.md) · [Skill-RSI 门控](../../skills/skill-rsi/references/PROTOCOL.md)
- **何时停止。** 第一候选先登记评测窗口、最小有用改进及成本上限，再打开保留集。示例门槛为误报率绝对下降 5 个百分点且配对区间支持改善，新增严重漏报、无依据的确定结论和误投均为零，严重提醒 p95 延迟增量不超过 5 秒。两机用于检验流程；4 周试点结束仍缺独立样本时标「证据不足」，父版本继续生效。具体样本量须按基线发生率、相关性与预期效应估算，这些数字为预登记建议。
- **从发布到生效。** 一次人工采纳绑定候选哈希、父版、评测版本与适用范围；兼容的新任务可固定到新版本。运行中的每次升级仍需用户选择目标并确认。界面分别显示已发布、有新版、待重启和已加载，最后一项需宿主对执行、代次和版本的回执。缺回执显示「加载状态未知」。出现严重退化则暂停该版本在受影响范围的新推荐；证据撤权时清除派生内容和待发送上下文，重算剩余证据。只有仍可复验的范围可以继续推广。

## 分批开发与放行

**执行顺序为 M0 → M1 → M2。M2 是第一个可日常使用的版本。** M0 完成后，客户端可用合成数据并行验证界面和交互。M1 提供真实任务与证据后，M2 进行双端联调；M3 依赖 M2 的身份绑定和宿主回执能力。M4 的离线准备可从 M1 开始，窗口版本采用依赖 M2 的 mylib 入口，向在途窗口应用升级依赖 M3 的确认链路。

MCP、Hook 和数据库设计归 mylib，双端布局与宿主交互归 SuperMonoAgent。各阶段通过独立开关启停。日常数据库与运行凭据在服务数据目录。热库和归档容量分开监控；多写实例或写入排队超过约定服务目标时再评估 PostgreSQL。以上均为设计与未来验收条件。

## 开工清单与最终验收

1. **M0 第一项交付。** 在两台授权测试机登记测试项目、主机安装 ID、工具及版本、宿主能力和计费账号别名。为 `report_step`、`search_task_events`、`get_task_status`、`record_usage_snapshot`、`get_usage_overview` 编写请求、响应及错误样例；一并固定任务交接、wiki 修订和数据恢复契约。凭据保存在所属运行环境。
2. **M1 做最小纵向联调。** 先用合成事件贯通「本地 wiki → MCP → SQLite → 查询」，再接两个真实工具。测试断网、幂等冲突、双机同名窗口、接手与复验；桌面关闭时上报继续。
3. **M2 交付首个只读试点。** 分别验收 Codex、Claude Code、Grok 的 Hook 和额度字段，建立逐工具能力表；一次事件一次查询义务，失败仍回写状态。桌面、手机和平板均能看「对话／待处理／额度／mylib」。对照官方来源验证真实余量；实测 20 窗口的响应与上下文预算。真机或厂商能力待验的部分逐项列出。
4. **M3、M4 分别验证投递和学习。** 用测试会话覆盖确认后一刻换代、撤权、接手和回执丢失；再用一项已有对照证据的失败生成候选、回放和评估、人工采纳、向新执行发布并核对加载版本。两条链路均具备独立回退记录。
5. **最终演练。** A 机 Codex 额度不足，B 机 Claude 接手，Grok 针对同一工件复验。模拟 A 离线补交、额度查询限流及数据库换库。用户从 Android 查到最新执行、两份证据及分歧，在 Windows 选择具体窗口并确认反馈；随后从 mylib 查看获准共享的方法和实际版本。对照五项目标逐项记录测试数据、代码与资源版本、真实或模拟范围、结果及遗留项。

**推广和停止条件。** 隔离试点通过后逐项目、逐工具启用，保留旧前端入口。任何新增的既有功能回归、越权读取或误投都停止扩围，关闭相关开关并在原用例复测。恢复时保留运行中的 PTY、草稿、已确认事件与待办；成功回退也要记录证据。各阶段按验收放行，排期在 M0 确认工具和账号能力后估算。 [SuperMonoAgent 回归清单](/D:/aicoding/supermonoagent/.omx/plans/multi-agent-hub.md) · [桌面与安卓交互](/D:/aicoding/supermonoagent/DESIGN.md)
