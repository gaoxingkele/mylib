# Design a Confound-Isolating Diagnostic
_id: `controlled_diagnostic_design` · journal=`ieee-internet-of-things-journal` · primary_count=3_

**Plain alias**. _Design a confound-isolating diagnostic_

**Operational signature**. confound → controlled instances → isolate true property

**When to apply (in `ieee-internet-of-things-journal`)**. When local accepted papers in this venue execute this move (see examples). Prefer composing with a journal-house pattern below.

## Success conditions (from local accepted sample)
- Contribution names a concrete bottleneck and closes it with the operational signature above.
- Evidence matches venue bar (baselines / case / figures) as observed in tagged papers.
- Differentiation stated vs nearest prior stack (not only 'we combine X+Y').

## Failure modes (desk-reject risks adapted from IdeaSpark reject lessons)
- Pattern executed as a mechanical wrapper of known modules without new identifying structure.
- Preservation/claims supported only by a single toy case or confounded ablation.
- True bottleneck left untouched while swapping a surface operator.
