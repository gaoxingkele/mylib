# 电网科技项目评审

用于电网/能源科技项目的可研、申报书评审，以及从年度/重大指南提炼审查方法。先执行[国内评审适配](review-revise.md)，再按项目加载[领域能力卡](power-grid-review-profile.json)。不新增评审叶技能，不改变现有六角色。普通写作或其他领域评审无需加载本页。

## 先确定评价对象

记录申报方、具体批次、项目类别、阶段和核验日期。国网总部科技项目、国家智能电网重大专项、南网科技项目是不同体系；技术领域分类也不等于基础/应用/开发研究或装备/示范项目类别。立项、采购、中期、验收、成果评价分别核对，不把验收规则或采购评分当立项评分。

当前指南、模板、补充通知和适用制度决定本项目要求；适用法规与业主安全要求另行核定。科研评价标准、行业标准、历史指南和案例提供参考，不自行覆盖本轮要求。内部管理细则、取费规范、正式评审表未见时列缺口，不编造权重、通过分数或费率。来源发生冲突时保留两处原文和适用性问题，交申报主体核定。

能力卡收录22个公开来源入口与10种推断能力，核验时点见 `verified_at`。多数标准只读到题录/适用范围，不能引用未读条号或把题录转成强制扣分。每次实际引用重新核查版本、状态、适用范围与正文；标准计划、废止版本和指导性技术文件要准确区分。卡片里 `type: inference` 表示审查问题的设计建议，不表示标准逐条规定了这些做法。

## 六角色如何使用能力卡

| 角色 | 电网领域检查 |
|---|---|
| 1 写作与格式 | 核本轮栏目、限字、术语、单位和附件；工况、指标、引用是否表达准确 |
| 2 内部一致性 | 指南—目标—任务—输入输出—指标—测试—交付—进度—资源是否对应；统计口径有无漂移 |
| 3 匹配与价值 | 真实业务场景、现有方法缺口、创新增量与技术经济路径；按项目类别评价 |
| 4 科学问题与方法 | 机理和约束怎样进入算法；对照、消融、失败场景、置信和工程验证能否支持AI增益 |
| 5 经费、团队和条件 | 人员、数据、接口、场景、报价、依赖许可、复用贡献与权属；计划和已落实证据分开 |
| 6 仲裁 | 来源是否适用当前机构/批次/类别/阶段；剔除旧版误用、重复意见和越界要求，记录分歧 |

按需选卡，不要求每个项目加载所有标准或执行所有试验。电网安全判断需要适用运行、调度、保护及设备条件；稳态结果不自动证明暂态或保护安全。报告解析准确率不自动等于专业诊断准确率。知识图谱或多智能体存在不自动证明无幻觉，仍需业务规则版本、证据、拒答/转人工及工具权限方案。

科研指南中的参数、规模、时长、国产化比例、制造产能和资金条件属于该项目。可以学习“为什么需要这些证据”，不要把数值迁移给另一个申报。软件原型不自动承担装备型式试验或批量制造要求；可研阶段也不要求未来验收已经完成。

## 从大型指南学习的方法

先区分原始指南、摘要清单、部分批次表、策划稿和评审记录。做结构清点，再抽取代表性任务和指标，保留工作表/单元格或PDF物理页。把事实转为“判断问题—失败模式—需提供证据—迁移限制”，并明确标为推断。不同年度不是同口径完整样本时，不计算总体趋势；指南是否发布、指南技术分数不能当申请书获批标签。

私人材料和具体项目原句留在项目目录。维护共享能力卡时仅使用公开来源和通用方法，测试使用合成案例；不提交内部评分、申报书正文、未获公开授权的指南全文或私人路径。知识提炼不是模型微调或专家能力认证；需要独立案例和真实同行纠错检验。

## 评审意见的依据适用性检查

仍按国内路线保存原句、定位、依据和修改建议。电网评审另准备一个项目级JSON，记录来源范围与意见采用方式，使用本地校验器：

```powershell
python proposal-writing/scripts/validate_review_basis.py project-review-basis.json -o basis-check.json
python proposal-writing/scripts/validate_review_basis.py --profile proposal-writing/references/power-grid-review-profile.json
```

`basis-check.json`只验证结构和适用性声明，不联网，也不证明条款真实、实际授权或技术效果。项目级basis允许本地材料路径；共享profile只使用公开URL，排除本地source_path。来源信息应来自本轮读取结果，不能为通过检查将题录改成已读全文，或将引用声明改成已核实。完整输入字段与演示见[依据记录格式](review-basis-schema.md)。

对正式要求使用 `claim_type: requirement`，核验已读原文、版本、生效日期和适用范围；对学习所得使用 `inference` 或 `recommendation`，对编号/状态等题录信息使用 `catalog_fact`。条件尚未核定时，不做硬性违规结论。推荐性标准被本轮文件明确采用时，逐来源记录采用它的文件及原文位置；声明本身不能替代原件核验。

用户明确要评分时，可以给标明“内部工作评分”的维度、理由和改进项。文本质量与材料状态分别评价，材料分档不叫材料完成百分比；不从指南或标准题录臆造官方权重和获批概率。总分不能抵消资格、经费或授权缺口，不适用章也不按内容缺失扣分。
