# 多专家交叉评审与协同修订

从 [申报书评审入口](../../references/review-revise.md) 进入。沿用项目的指南、模板和证据台账。交叉评审要回答一个容易被单人审稿漏掉的问题：为某一席解决的问题，会不会使另一席原本认可的论证失效？

## 建立基线

1. 固定要审的实际版本、当轮已有材料、允许改动的范围和轮数。只评审时交付意见；需要修改时保留基线与各轮可打开的版本。用户要求按“六席三轮”做时，基线另计，共评四次。
2. 按用户指定的角色组建评审组，给每席稳定的代号和职责。科技项目可从下表起步，根据研究对象替换专业席。主持人负责取舍、落笔和版本核对，不代替专家投票。
3. 让各席独立读同一份实稿，涉及配图者查看渲染页。环境支持时用独立子代理，各轮尽量保留原席位。若只能由同一模型分角色执行，在报告中注明“单模型分角色模拟”。始终标明模拟身份；没有回执的席位列为缺评。
4. 仅在用户需要评分时启用下述百分制。首评前固定角色、维度、量尺与分母。换席、换尺或换项目时标出断点，另建可比序列。

| 席位 | 该席要解决的判断 |
| --- | --- |
| A 算法或核心方法 | 输入、输出、比较对象、对照和测试隔离是否足以检验主张？ |
| B 交叉应用 | 谁在什么场景做什么，交接、安全边界、任务成功由谁确认？ |
| C 世界模型与物理引擎，或所在领域的机理专家 | 哪些量可以直接计算或测量，哪些需要建模？校准与独立核验能否分开？ |
| D 产业与交付 | 谁实施、谁复测、谁签收？部署成本、产品收入和真实订单各凭什么材料？ |
| E 普通用户 | 请用自己的话复述一次操作。哪句话、术语或段落让你接不上下一步？ |
| F 配图 | 实际看图后，能否说出对象、关系、分支和证据来源？指出一处适合加图、删图或改图的位置及原因。 |

## 一轮怎么做

**独立提出意见。** 各席先给出版本、段落/图号、原文短引、风险、依据、建议改法和验证办法。需要评分时附四项分数。将“项目尚缺测量记录”和“正文没写清测量方法”分成两条；只有后者能单靠改文解决。

**交换意见并交叉投票。** 主持人去重后把各席意见和拟修改处发回相关席位。每席回答：“当前版本在对方负责的方面，与我的判断是否相容？”对其他每席逐一给 Y（认可）、C（有条件，列成立条件）或 N（冲突，指明冲突文本与影响）。同一组双方可以投出不同票。有分歧或改票时记下理由和版本位置。终轮再单独询问是否同意采用整稿，并列出仍需外部补证的事项。

**仲裁后修改。** 把冲突双方的要求写在同一条记录中，给出采纳、合并、暂缓或驳回的理由。按指南和证据判断，优先解决会影响结论的分歧。常见的处理是把简明示例放在正文，把参数保留在技术表；或把运行时使用的数据和只供事后验收的数据画成两路。对已处理的意见写明段落、图注或验收表发生了什么变化。新增实证、预算、合作承诺均需有来源。意见较多时复用[修订台账格式](../../references/review-revise.md)。

**用新版重新评。** 各席打开实际产物并复核受影响的文字、表格和图片。核对目标与预算、正文与图中的箭头、原有引用及待补项。模拟席可以维持原分、降分、保留条件或撤销认可。若用户指定轮数，交付相应轮次；若要求“直到一致”，在达到共识、达到约定上限或剩余分歧只能靠新证据解决时停止，报告具体状态。不能用预填上升曲线、改分母或删去反对席来制造共识。

## 如何计分与交付

评分四项依次为**问题清楚、方案可行、验证可复核、证据边界**，各 0–25 整数分。用同一把尺判断每个维度：0 表示缺失或自相矛盾；约 12 表示有叙述但关键步骤需要猜测；约 20 表示可按文执行并指出余下条件；接近 25 需要能定位、能复核且没有该维度的重要文本缺陷。分数针对文本设计。现场效果与获批情况另须证据。

- 每席总分为四项之和，全组均分为各席总分的等权平均。用原始整数计算，最后显示一位小数。
- 有 `n` 席时共有 `n(n−1)` 张定向票和 `n(n−1)/2` 对关系。只有两席互投 Y 才计一对双向认可。六席共有 30 票、15 对。C、N 和缺评分别报告；缺评先补录，期间保留已有文字意见、暂停该轮完整统计。
- 把分项分和逐席票按[合成示例](references/example.json)录入，版本按评审时间排列。从库根执行下列命令，[计分器](scripts/score_rounds.py)核对完整性并重算。文字意见、异议理由和外部证据另随报告保存。

```sh
python proposal-writing/skills/cross-panel-review/scripts/score_rounds.py proposal-writing/skills/cross-panel-review/references/example.json
```

示例从 1/3 对双向认可变为 2/3 对，B 席从 74 分降为 72 分。非对称票保留两个方向。可用下列一行把计分表与书面异议对齐；整稿采用意见另按席位记录，不能从全 Y 或高均分代推。

| 版本 | 评议席 → 对方 | 票 | 实稿位置与影响 | 成立条件或修法 | 新版复核位置与裁定 |
| --- | --- | --- | --- | --- | --- |
| 合成示例 baseline | B → A | C | “试用流程”图未注明由谁确认完成，使用者无法复做 | 补上签收人和判据 | 待 B 席复核 |

交付最终稿与历轮版本链接、四项分及总分、逐席投票和双向认可数、关键分歧如何解决、最终采用意见、未解决事项。只评不改时以修改建议和复核条件收束。项目的原稿、配图、身份信息和真实评分记录留在项目目录；共享技能库保存可复用的方法与合成示例。
